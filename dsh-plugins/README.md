# dsh-plugins —— 面板共通约定

本目录下是 DSH 会话里热加载的可视化面板（诊断 / 指标 / 自演进）。**每个面板的 README 讲它自己
的信息架构；本文件讲两个面板必须一致的约定**——色语、排版、文案。放着不统一的后果是实测过的：
同一界面里两个面板风格不同，读起来像两个产品。

一次改一个面板时也请读这里：这些约定是**跨面板契约**，改动要走两个面板一起改 + 回归闸门。

| 契约 | 权威实现 | 机械检查 |
|---|---|---|
| 颜色角色 | 每个 `panel-client.js` 的 `--c-*`（文字，需过 WCAG AA）/ `--acc-*`（装饰，两点面板逐色同值）/ `--fill-*`（实心徽标底）/ `--btn-*` | `python3 scripts/check_panel_tokens.py` |
| 字号与行高 | 8 档 `--t-md2 10.5` → `--t-2xl 18`（基准 `--t-base` 14.5）；行高 `--lh-tight/base/prose`（中文需 ≥1.6） | `node scripts/panel_render_check.js`（断言：声明 8 档、无硬编码 font-size、最小档 ≥10、基准档 ≥14、两面板同值域） |
| 面板文案 | 本文「文案规范」节 | 同上（八条里只有"无字面星号"一条可机械判） |
| 只读边界 | 面板是只读可视化 + 指令生成器；不做决策与写入 | 人审（`skills/preload-panel/SKILL.md`） |
| 依赖缺失时的退化 | 拿不到数据时给一行说明 + 可行的下一步，不占位、不拿别处的数据冒充 | `node scripts/panel_render_check.js`（退化路径一节，含 5 个缺件用例） |

## 文案规范

面板文案是可核对的信息，不是叙述。以下八条是判据，改文案时逐条对照；**反例全部取自本仓库真实
出现过的写法**（多数来自自演进面板的早期版本）。

| # | 规则 | 反例 |
|---|---|---|
| 1 | 一条只说一件事，超一个分句就拆行 | "这不等于是没问题：先看覆盖面，没报越界与没被检查是两件事" |
| 2 | 不用比喻与拟人 | "一堵只增不减的墙""改动落在机器的哪一层""这个数高是症状" |
| 3 | 不用对偶与排比 | "不是变好了多少，也不是作者想优化什么" |
| 4 | 不用强调副词 | "唯一真实的负反馈读数""恰好可以充当验证者" |
| 5 | 引号不做强调 | 给「稳定」加引号暗示反讽；「」只用于引用字段名、控件名或原话 |
| 6 | 不自我评价 | "如实标注""不冒充通过""诚实的实验记录"——如实是默认要求，不必在界面上声明 |
| 7 | 内部标识符不上屏 | `state: ok`、`capability_readout`、枚举名 `metrics_compare`；正文用中文名 |
| 8 | 命令与路径原样给出（可复制），其余一律中文 | 正文里混用 `soft_cap`、`routed_accuracy` 当普通词 |

**专有名词用术语而非修辞**：说"零否决记录""外部验证占比不足""引用路径失效"，不说"从未说过不"
"自证过多""依据已消失"——后者读着顺口，但没法当判据名引用，也容易被读成价值判断。

三条配套口径：

- **判据的标题与解释是数据**（如 `proposals/gates.yaml`、`metrics/gates.yaml`），改文案不必动代码；
  带数值的读数模板留在脚本里（格式化贴着维度定义）。
- **文案改了要同步改钉它的断言**。`panel_render_check` 大量断言直接匹配文案，只改一边的后果是要么
  闸门红、要么断言悄悄失去意义（假绿）。实测一次措辞重写牵连 18 条断言。
- **哪些规则能硬化**：八条里只有"无字面 Markdown 星号"同时满足检查准入三条件（机械可查 / 后果确定 /
  复发 ≥2 次）。其余七条属判断性规范，对照本表人审——不为"AI 味"造硬门，那是假装硬化（原则六）。
  星号的后果是确定的：它会原样渲染成字符，并且出现在**可复制的指令**里被粘进对话。

### 行话的取舍（有意保留的例外）

规范第 7、8 条不是"一切都要说人话"。以下两类**故意保留原值**，因为翻译会损失可核查性：

1. **原始字段值与枚举**：`process_friction`、`soft_cap`、`resolved` / `not_resolved` / `partial`
   等。它们是卡片、`gates.yaml`、`trace-status.yaml` 里的真实取值，改成中文后读者对不上原文。
   需要时在展开的技术视图或 tooltip 里给出，而不是替换正文用词。
2. **仓库内路径与命令**：`scripts/metrics_health.py`、`traces/`、`python3 scripts/...`。
   按规范第 8 条原样给出，可复制即其价值。
3. **已成术语的比喻**："体检"（`metrics_health.py` / `evolution_health.py` 的输出、`docs/metrics.md`
   与面板正文都在用）。改它要连脚本输出与文档一起动，收益为零。
