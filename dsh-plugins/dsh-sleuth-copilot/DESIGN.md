# 诊断交互层：插件点地图与取舍

这份文件记录「为什么是这几个面」与「还有哪些点可以考虑」。实现清单只看
[README.md](README.md)；这里放判断依据。

## 读者与场景

- 读者：现场工程师与技术支持，白天连续处理多单；一只眼看日志，一只眼看着对话。
- 任务循环：收集材料 → 判断 → 给结论 → 回报 / 沉淀。
- 一次中断的代价：切到别的界面、找到那一单、再切回来。三分钟以上的诊断会被切走十几次。

## 六条交互原则

1. **不打断**：读状态与常见写入都在对话内完成。
2. **渐进披露**：默认一行；展开才给细节；偏好在下次打开时保留。
3. **下一步只有一个**：主按钮永远指向当前最该做的事，其余进「更多操作」。
4. **写入可核对**：写前给出对象与字段，写后给结果；并发冲突给原因与刷新入口。
5. **一处定义、多处一致**：三个面共用同一份数据、同一套动作措辞与同一份偏好。
6. **降级可读**：没数据、没权限、写不了时给出原因与下一步，不拿别处的数据顶上。

## 三个面为什么这样分工

- **状态条**：常驻、离输入框最近，负责「现在」与「下一步」。默认收起成一个居中的窄胶囊，点开才是完整两行；收起选择记住。
- **工具条入口**：状态条收起时仍在手边；角标把「有几单欠回报」变成环境信息，不打断。
- **总览**：全库横向比较与批量动作的主场。浮层而不是新页面，关掉就回到对话；键盘操作减少鼠标往返。

没有做第四个面（顶栏胶囊）：同一个入口放三处，读者要记「哪里能点」；两处已经覆盖
「在输入区」与「不在输入区」。

## 展开态怎么收起

- 原先只有右上角一个箭头能收，目标小、离视线远；展开容易、收起要瞄准角落，操作成本不匹配。
- 点状态条外收起是浮层的通用约定，点击目标覆盖状态条以外的整片区域。点进输入框不算：收起会让输入区上移，
  正在定位光标的点击会被带偏。
- 不想被收起的人用「展开后常驻」：按钮在右上角，选择与其他偏好一起存在本地。
- 不做静置自动收起：诊断进行中有人靠它盯状态，自动收起比多点一下更糟。
- 判断「这次点击是不是在状态条里」用**手势起点**（`mousedown` 时记）与 `composedPath()`，不看点击瞬间的
  `contains(target)`：菜单项、选择器行点击会把自己从 DOM 换掉，到 `document` 时 target 已 detached，
  只看 `contains` 会把这类点击当成「点外部」收起整条，刚展开的表单跟着消失。
- 静置淡出只改透明度。`prefers-reduced-motion: reduce` 只把过渡去掉（2.8 秒后瞬间变淡），不取消变淡：
  Windows 关闭「动画效果」时 Chromium 报 reduce，若连变淡一起停掉，读者看到的是「这个效果没了」。
  透明度变化不属于位移或缩放类动效，保留它与无障碍设置的意图不冲突。
- 「更多操作」与选择器浮层优先向上展开；上方可用空间不足时向下并限高。量的是状态条上方可用的视口高度，
  以及最近一个会裁内容（`overflow` 为 auto / scroll / hidden）的祖先顶边，避免浮层被裁掉或被顶栏盖住。

## 第二行放不下时收哪一段

- 平台、框架来自 trace 的自由文本，`detected_platform` 能写几十字；性质是中断 / 精度 / 性能三类枚举。
- 放不下时有换行、溢出、截断三种处理。
- 换行让状态条高度随数据变，输入区跟着上移。
- 溢出把文字顶出状态条：实测 760px 宽的状态条里，最后一段身份标签被顶到条外；窄窗口下还越过窗口右边界。
- 选截断：平台 / 框架 / 性质与「在等什么」按省略号收。两段同时按比例收，没有谁先收。
- 身份标签保留完整宽度：它是离散的状态标签，逐段裁会变成半截标签。极端宽度下由第二行容器裁断，同样没有省略号。
- 截断不丢信息：两段都带 `title`，鼠标悬停看全文。完整值在诊断总览里一步可见，键盘能打开总览。
- 不在 JS 里按字数裁剪：字数与像素不等价，中文、ASCII、字号都会让同一字数占不同宽度。
  裁剪规则放 CSS，换主题或改字号时自动跟着走。
- 「在等什么」提到第二行主文本（12px、正文色），平台 / 框架 / 性质降为它前面的次要信息。
  这一段是 agent 写的行动线索，原文常是一整句；原来按 11.5px 次要色排，读者扫到的是标题和按钮，看不到卡点。
- 状态文字（进行中 / 已定位）从首行移到第二行（排在进度与第 N/6 步之后、平台 / 框架之前）：首行的空间要留给案例标题，状态点已经用颜色表达了同一件事。
- 进度轨从 11px 横段压到 7px：六段横杠只传达「第几步」，读数由紧随其后的「第 N/6 步」提供，不必占三十多像素。
- 知识库落后提示改成一行 11px 内联文字加两个文字链：它是维护性提示，原来的通栏琥珀块会和诊断状态抢同一块位置。
  含面板代码的那句仍保留，跟在后面，过长时截断并在悬停里给全文。

## 收尾表单只对进行中的单给

`trace_transition.py` 对终态单把「`--to resolved`」解释成 correct-ending：界面若照常给「已定位」，
点一下会成功写入一条 `resolved → resolved` 转移，重写收尾方式，并用表单默认值覆盖 severity / fix_emitted。
这两个字段分别是「等上游」的判据与指标来源，写错不报错。所以收尾三项只对进行中的单出现。

终态单另给两个明确入口，动作与目标都来自 `_trace_state.py` 的 `actions`：`correct-ending` 按目标渲染
「改收尾方式：已定位 / 已转交 / 不再跟进」（换状态时脚本先写一条重新打开再收尾），`backfill-ending`
只补当前状态的收尾方式。界面不重算状态机；投影没给 `actions` 时不显示这两项。

收尾表单另补两处：`summary` 是 close 动作的 fillable，缺它脚本直接拒（表单预填 trace 现值，可改）；
`fixEmitted` 初值取 trace 的 `fix_emitted`，没有记录才回落 true，避免把 false 写成 true。
所有下拉框的选项都优先取投影里的词表（`trace-status.yaml` 是唯一来源），没有该段时才用常量兜底。

## 数据新鲜度与「选中对单」

- 首屏成功后轮询失败不再静默：保留旧数据并标「数据可能过期」，折叠态胶囊、展开态标签与总览顶部都会提示；
  下次成功读取时清掉标记。取数从没成功过（缺 Python、坏检出）时，总览给原因与重试，不停在骨架屏。
- 总览选中项按 `sessionId` 记住。10 秒刷新会让列表按 `updatedAt` 重排，只按下标存的话右侧详情与动作条
  会静默换到另一条单上，读者按着 A 单的按钮改的是 B 单。
- 表单打开时冻结内容指纹（CAS 令牌），菜单开着期间外部改了 trace 会报冲突并提示刷新；用提交那一刻的
  新指纹会让屏幕上的旧值直接覆盖外部改动。

## 沉淀入口按状态判，不按候选判

`needSed`（trace 里有 case 候选）是 agent 的建议，不是入口的前提：没有候选的单调不出「沉淀为 case」，
读者就只剩「沉淀状态…」这个改状态的入口，真正要起草时无处可点。所以菜单、收尾清单与命令面板的沉淀入口
只看三件事：还没沉淀、这单不是空骨架、命中的 case 不在库里。候选只在文案上区分（无候选时注明按 trace 起草），
以及「可沉淀」筛选与批量条里继续表示「agent 已标候选」。

## 沉淀视图（v1）的四条判断

1. **队列放总览，不新开页面。** 诊断与沉淀分别回答「这一单」与「这一批」，但入口多一个就要多记一处；
   总览里加「诊断 / 沉淀」切换，键盘与动作模式复用。
2. **合入状态是「已提 PR」上的属性，不是第六步。** 队列只有五步；`state` 带 `checked_at` 与
   `source`，查不到写「未确认」，不由分支是否存在推断。多一个阶段会让状态机与文案一起变复杂。
3. **提 PR 指令默认短。** 流程在 `/knowledge-groom` 里，界面只补 agent 看不到的批次、决定、
   落点与边界；命令细节折叠，避免出现第二份流程说明。
4. **远端目标只问一次，只列事实。** 目标存在主检出的 `.local/settings.json`（旧台账的 `target` 段仍读，
   用于迁移）；选择器列 host、平台、HEAD 分支、适配器/token 状态，不预设哪个是团队仓、哪个是上游。
   场景没收敛前，默认留空。

扩展面：PR 平台是 `scripts/platforms/` 下的适配器；界面只读 `{state, checked_at, source}` 与平台显示名，
新增平台不改界面与核心脚本。doctor 从适配器声明里查 token/命令，不写平台特判，也不代装。

## 沉淀队列跟到 PR 合入（v0.16）

1. **队列的对象是事项，不是 inbox 草稿。** 草稿进了 `.done/` 只是「本地收尾完成」，不等于事情做完；
   只要 PR 没合入，就该有一行可看。`.done/` 的标题、close-log 的决定、台账的 PR 三者合并成一行，
   合并只在 `sediment_state.py` 做。
2. **出队等合入。** 合入前收尾会先删掉人的决定与评估证据，PR 被拒时只能重评；trace 也会提前写
   `knowledge`。`groom_close_draft.py` 在 PR 不是 merged（含 open / unknown / closed）时拒绝执行，`--allow-open-pr` 才越过。
3. **查合入就地做。** 一次查询是台账写动作，不是对话动作。批次条「查全部合入状态」跑
   `pr_status.py --check-all`；详情里的「查合入状态」跑单条，同一个动作只留一个入口。
   批次条的主操作跟当前筛选：切到「待合入」时主按钮换成查合入（只剩已合入行时换成收尾），
   混合队列在其它筛选下保留一个次级入口。这里只换按钮位置，两个动作的作用域都还是整批：
   `--check-all` 查台账里全部待合入的 PR，groom 指令针对整份队列。
   成功与失败都回提示：单条给 PR 号与新状态，整批给更新条数，失败给原因。
   没有写权限时单条与批次都回落到生成查证指令；没有适配器或 token 时在行内给原因。
   写本地文件被系统拒绝（只读属性、访问控制、被占用）或沙箱 / 档位拒绝时打开指令弹层：原因、查到的状态、
   可执行命令、写的是哪份文件与排查步骤；点「填入输入框」交给会话里的 agent 执行。查询类失败与读坏台账不生成指令。
   状态只认平台查询或人工确认，不从分支推断。
4. **关闭的 PR 给恢复命令，不自动搬文件。** `.done/<key>` 移回 inbox 会改变队列，交给人点一次；
   移动命令按平铺 / 目录两种草稿形态生成。草稿还在 inbox 的关闭 PR 行给「撤销沉淀」：撤销会清掉
   台账里这条已关闭记录（undo-log 留 PR 的编号与地址），PR 本身在平台上不动。
5. **过期压过待合入。** PR 开着但评估已经过期时，队列先让人重跑 groom；PR 记录留在详情里，
   不让人按「查合入」去做一件已经不该做的事。
6. **平台一直查不到时有人工兜底。** 详情里的「手动改状态」按人确认写 PR 台账，来源记为「手动确认」。
   四档与 `pr_status.py --mark` 的 `open / merged / closed / unknown` 一致，下一次查合入仍以平台结果为准。
   它与查合入写同一份台账：写不进时同样给指令，不让读者对着不可写的文件重试。
   没选推送目标不等于没有 PR：这句提示只在要开 PR 的行出现。

## 队列变大时的取数开销

1. **同一评估基准只查一次 git。** 新鲜度对每份草稿要查三类 git：目标 ref 解析、祖先关系、
   知识库 diff。评估记录常指向同一个快照 commit，原来逐份各起子进程，300 份草稿取一次数要起
   726 次；按 ref 与 commit 对缓存后是 12 次（夹具里有两个基准），判据不变。
2. **批次指令只出一份。** 待提 PR 的指令本身逐条列草稿，复制进每一行会让 payload 随条目数平方
   增长：600 份已决定队列 24 MB → 1.4 MB。界面按 kind 从顶层 `prompts` 取，行内只留逐行不同的
   恢复命令。
3. **YAML 走 libyaml 快路径。** 一次取数要解析上百份草稿与评估记录，`groom_common.load_yaml`
   改走 `_yaml.Loader`（CSafeLoader，没编出 C 扩展时回落纯 Python）。解析结果与 `safe_load`
   相同，异常措辞随解析后端不同。
4. **同一 PR 只查远端一次。** 一批决定常被提成一个 PR，台账里几十份草稿可能各有一条指向它的记录。
   查合入按 PR 身份（平台、repo、号、URL）分组，每组查询一次再把结果分发给组内每份草稿；
   查询失败时同组写同一份「未确认」。界面按同一套归一后的键计份数，行内标出「同 PR N 份」，
   让读者知道这些行是同一个外部事项。

本机合成夹具（`scripts/bench_sediment_queue.py`）实测取数一次：300 份混合队列（60 份未评估、
120 份待决定、120 份需重跑）6.7 秒 → 1.1 秒；600 份已决定队列 17 秒 → 2.3 秒。有 libyaml 的
Python 上是 0.5 秒与 0.8 秒。

## 多选与撤销的边界

1. **复选框常驻，不做「多选模式」。** 点行内容仍然是看详情，`Enter` 的语义不变；模式开关会让同一次点击在两种含义间切换，读者要记当前在哪一档。
2. **范围永远写在按钮上。** 未勾选时是「整批」（当前筛选含搜索词），勾选后是「所选 n 项」；主按钮与菜单项都带条数。范围不在别处默认，读者不必从筛选反推。
3. **选择集按稳定 id 记，跨筛选保留。** 对不上行的 id 单独计数（「k 项已不在队列」）并给移除入口，不从选择集里静默删掉——静默删会让「已选 3 项」变成 2 项而没有交代。
4. **撤销分两级，动作这一级按面板看得见的状态分三档。** 选择态可退（`Cmd`/`Ctrl`+`Z`，最多 5 步，恢复选择集与筛选 / 搜索词）；指令类回执只写「已填入，尚未发送」，给清空与复制名单；面板自己写台账的动作才反写旧值。面板不知道 agent 是否执行，所以不写「已撤销」。
5. **所选范围的批次指令由 host 现算，不在客户端拼第二份流程。** `sediment_state.py --prompt-keys` 只收窄指令名单，队列与计数仍是全量；`pr_status.py --check-all --only-draft` 只查所选。客户端拼指令会与 `/knowledge-groom` 的流程漂移。
6. **查合入在只读档位下不回落整批。** 整批查询会写未选中的行，范围静默变大比不给入口更糟；这时只提示只读。
7. **数据可能过期时先刷新再动。** 主操作置灰，其余批量动作点了先提示，选择集可能已对不上台账；复制与查看仍可用。
8. **不做批量收尾 / 批量改状态。** 每单的 `severity`、`fix_emitted`、`summary` 不同，共用一份会静默覆盖（见「收尾表单只对进行中的单给」）。
9. **不做跨视图共享选择、选择持久化、全库全选。** 两个视图的 id 不同域；隔天恢复一批「已选」而行早已变状态；全库全选把一次误点放大成整库操作。
10. **复选框是行外的独立按钮，不嵌在行按钮里。** 行仍是 `<button>`（`Enter` / 双击语义不变），复选框是兄弟节点、`role="checkbox"`、`tabIndex=-1`：鼠标点它改选择，键盘用空格切换焦点行的选择，`Tab` 顺序不因每行多一个控件而翻倍。

## 总览面板的排版与控件

- 字号取八档、字重取四档，值写在 `.scp-pal` 的 `--scp-fs-*` / `--scp-fw-*` 上；命令面板、表单控件与浮层提示同样从这两组 token 取值；状态条共用的 `.scp-menu-note` / `.scp-case` 仍是固定值。
- 诊断视图的筛选从标题栏移到左列搜索框下方，与沉淀视图一致。两个视图都在这处筛选，切换视图后位置不变；标题栏只留标题、视图切换与关闭。
- 详情按「案例标题 → 识别行 → 问题背景 → 区块」排列。不把案例首句放大成标题：真机 trace 的 `summary` 常见
  一两百到七八百字，16.5px / 650 会渲染成七八行粗体。但也不能没有标题：右列顶部补一行 13px / 600 的单行标题（截断 + 悬停），
  解决从列表点过来后确认不了「这是哪一单」。识别行保留状态、身份标签、第 N/6 步与更新时间。
- 左列宽度改为 `clamp(280px, 34%, 380px)`，1200px 以上固定 400px，上下堆叠断点从 760 提到 900。
  1440px 窗口与原来一致（400px），1000px 窗口左列从约 394px 收到 320px、右列多出约 74px，正文不再被压到每行四十来字。
- 沉淀视图右列的草稿详情用同一套案例标题、识别行与正文背景样式，两处不再各写一种。
- 问题背景按正文 13px / 1.75 排四行，超出时给「展开全文」，同一段不在底部重复。展开入口先读实际溢出
  （`scrollHeight` 与 `clientHeight` 比较）；替身渲染拿不到布局尺寸时，退回 110 字近似。
- 摘要里的路径、错误码、函数调用与 `XxxError` 走等宽字加浅底（`inlineTokens`：只按形状识别，不改文本）；
  等宽片段与正文同字号：原来 11.5px 比正文 13px 还小，被缩小的恰好是函数名、错误码与路径。
  展开状态按单号记，切到别单回到收起。
- 区块标题回到 12px / 600 次要色：11.5px 在长详情里找不到落点；卡片边框 72% 透明度、圆角 10、字段标签 11px 维持。
- 「在等」结论行与「在等材料」清单合成一个「还缺什么」块：原来两块各自带底色和卡片，读者要读两段才知道缺什么。
- 收尾清单的完成项弱化（浅色勾、次要色标签），待办项保持正文色与实心圆点；绿色实心勾原来是一列里最亮的元素，
  表达的却是「都做完了」。
- 底部动作收成一个主操作、一个复制摘要和「更多操作」，常驻在详情底部，动作条上方加 20px 渐隐。
  主操作落到「复制结论摘要」时（已收尾、且没有待回报 / 可沉淀），不再重复第二个同文案按钮，也不再摆蓝色实心主按钮：
  这类单没有下一步。
  其余动作收进菜单，窄宽度下不再堆叠按钮。
- 沉淀进度轨的类名从 `.scp-step` 改为 `.scp-sed-step`（`-dot` / `-label` / `-note` 一并改名）。原类名与诊断详情里的「第 N/6 步」共用，进度轨画连线的 `::after` 因此落到了那行文字上，显示成一条盖住文字的灰线。
- 列表行只留状态性信息（状态 / 平台 / 框架 / 时间 / 步数），已排除条数移到详情字段；选中行加 2px 强调色左标记，
  待回报行加 2px 琥珀短标记并在行内标「待回报」，两者同时出现时只留一条短标记。
  行内时间从 11px 最淡色提到次要色（`--scp-muted`）：原来是 2.6:1，扫不到。
- 取数失败时主区居中给原因与重试，顶部计数与 tab 显示「—」，底栏键盘提示收起。读不到不是「0 单」。
- 空数据只画一份占位并给「刷新」入口：两栏各画一份「没有符合条件的诊断」、中间一份虚线加号，看着像两个入口。
  加载中单独一态：副标题「正在读取」、筛选计数「—」，主区保留「正在读 traces/…」。
- 过期提示写明上次成功读取时间并带「刷新」按钮；原来只有一句「点刷新重试」，屏上没有刷新入口。
- 命令面板顶部标明作用于哪一单，命令按用途分组（主操作 / 复制 / 查看 / 动作 / 导航）；主操作已是回报结果时，
  列表里不再重复一条同样的回报命令。
- 选择器底部在未固定时显示「当前：…」，并给当前行「当前」标记；已固定时改给「取消固定」。
  原来同一模式在条上是「最近一单」、在弹层里叫「跟随会话（自动）」，且点行会静默从跟随变成固定。
- 更多操作把「刷新 / 诊断总览」放进置顶的「常用」组，菜单超高时上下渐隐；「不再跟进」用错误色标出。
  菜单是固定在动作条上方的浮层：点触发器、浮层外任意处或菜单里的关闭键收起，不替换右栏详情、也不再吞掉底部动作条。
  原来没有遮罩时只能靠关闭键退出，读者点外面没反应，看起来像「关不掉」。表单模式的关闭键与「取消」
  也直接收起整个浮层：旧行为是退回「更多操作」列表，读者要点两次才关得掉。

## 写入安全

- 能力位来自当前会话沙箱档位；只读档位下写入项禁用并显示原因。
- 每次写入带内容指纹；冲突返回 `E_STATE_CHANGED`，界面提示刷新。
- 破坏性收尾（不再跟进）在菜单里单独一组；已定位与转交需要表单字段，不靠一次点击。
- 回报轴当前没有脚本写入口，界面只生成指令，不写 `feedback`。

## 验证边界

渲染冒烟与 Host 冒烟覆盖：状态分支、折叠偏好、点外部 / Esc 收起与常驻偏好、总览键盘、沉淀队列 / 指令 / 目标选择、写入参数、
能力位、CAS、真实脚本写入（在系统临时目录的 trace 副本上做，仓库不被改）。

未覆盖：真实页面排版、鼠标点击、深浅色主题下的观感。这三项只能人工确认。
