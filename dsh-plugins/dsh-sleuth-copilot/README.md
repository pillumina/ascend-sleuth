# 诊断状态条（dsh-sleuth-copilot）

DSH 会话里的一个独立交互层插件。它把诊断的状态、下一步动作与知识沉淀入口放进对话本身，
不改现有面板源码，可单独安装、单独卸载。

四个面共用一份数据与一套偏好：

| 面 | 位置 | 用途 |
|---|---|---|
| 状态条 | 输入框上方（`conversation.input.dock`） | 本会话诊断到第几步、在等什么、下一步做什么；可收起，收起状态记住；知识库落后上游时提示同步 |
| 工具条入口 | 输入框右侧工具条（`conversation.input.right`） | 打开诊断总览；有待回报时带角标 |
| 诊断总览 | 全帧浮层（`shell.overlay`） | 全库诊断一屏看完、键盘操作、复制指令、直接改状态 |
| 动作层 | 以上三个面共用 | 复制结论摘要与各类指令；收尾 / 重开 / 沉淀状态写入 |

## 为什么是这个形态

现有四类界面（诊断 tab、整页「Ascend Sleuth」、诊断记录浮层、侧栏行标记）都要先切过去才能看。
诊断本身发生在对话里：贴日志、判候选、再问一个缺口，状态与动作应当跟着对话走。

三个判断决定了现在的形态：

1. **状态条默认收起成窄胶囊、可展开、记住上次选择**。读者常要盯消息，信息块不能一直挡着输入区。
2. **下一步只有一个主按钮**，其余动作收进「更多操作」。多个平级按钮等于让读者每次重新判断。
3. **全库视图是浮层，不是新页面**。需要横向比较多单时打开，看完 Esc 关掉，不离开当前会话。

## 界面与交互

### 状态条

- 首行：状态点、范围（本会话 / 最近一单）、**人读的案例一句话**、状态徽标、主按钮、更多操作、展开后常驻、收起。
  案例标题取自 trace 的 `summary` 第一句，诊断单号不进标题；鼠标悬停看全文，点标题直接打开总览到这一单。
- 第二行：六段进度轨与第 N/6 步、平台 / 框架 / 性质、在等什么、身份标签（命中 case / 知识库未覆盖 /
  待回报 / 可沉淀 / 已排除几条）。平台、框架来自 trace 的自由文本，`detected_platform` 能写几十字；性质是三类枚举。
  放不下时平台 / 框架 / 性质与「在等什么」按省略号收，整行不换行、不越出状态条。截断的那段悬停看全文。
  状态条 720px 及以下时平台 / 框架 / 性质与身份标签不显示，在等什么照常显示。
- 收起态（默认）：输入框上方居中的一个窄胶囊（自动宽度，不占满一行）：状态点 + 案例标题 + 第 N/6 步
  +（欠回报时）「待回报」，点击展开成完整状态条。静置约 2.8 秒后淡到 34%，鼠标移动、页面滚动或聚焦输入框时回到不透明。
  变淡只改透明度；`prefers-reduced-motion: reduce` 只去掉过渡（变淡瞬间生效），不取消变淡。
  Windows 关闭「动画效果」时 Chromium 会报 reduce，旧版本把变淡一起停掉，看起来就是没有静置淡出。
  收起状态与常驻选择写进 `localStorage` 的 `dsh-sleuth-copilot.prefs.v2`，下次打开保持。
- 展开态的收起有三种操作：点状态条外任意处、焦点在条内时按 `Esc`、点右上角「收起」。
- 点进输入框不收起：收起会让输入区上移，正在定位光标的点击会被带偏。
- 想让它一直展开时点右上角「展开后常驻」；开着时点外部不收起，只有「收起」与 `Esc` 能收。
- 欠回报时状态点变琥珀色；诊断步骤前进（同一单第 N 步变大）时状态点轻闪一次，不改变高度与位置。
- 欠回报数量挂在页面标题前缀（如 `[1] 诊断`），切走再回来能看到；不发通知、不弹窗。
- `⌘⇧D` / `Ctrl+Shift+D` 在会话界面（状态条挂载的输入区）打开诊断总览，并选中当前跟踪的那一单；整页与设置页没有状态条，不响应。
- 手动选单：点左端范围标签（本会话 / 最近一单 / 已固定）打开选择器，可搜索并把状态条固定到任意一单；
  「跟随会话」恢复自动。固定按会话记住。
- 本会话有绑定轨迹时标「本会话」：原始会话号等于当前会话，或当前会话出现在某个 `resume` 事件里（标「本会话（续接）」）；都没有时兜底显示「最近一单」，并给出续接指令。
- 工作区不是 ascend-sleuth 检出时整条不渲染；检出内缺 Python 或脚本出错时给一行原因与重试。
- 「更多操作」与选择器浮层优先向上展开；上方空间不足时改向下并限制高度，避免被滚动容器裁掉或被顶栏盖住。点浮层里的动作不会把点开它的状态条一起收起。

### 知识库更新提醒

状态条还显示「本机知识库落后上游多少个提交」。
插件在宿主进程里的那一半（下称 Host 半）每 30 分钟检查一次，DSH 启动后约 3 秒先跑一次；
宿主进程没有定时器服务时这一段整体不启用。
检查只 fetch、不合并，也不改工作树与 HEAD。一次检查会更新远端跟踪 ref，并让 `scripts/kb_sync.py`
在主检出的 `.local/kb-sync-state.json` 里记一份它自己的失败冷却状态。
检查项与字段都以 `scripts/kb_sync.py` 为准，`python3 scripts/kb_sync.py --show --json` 可以单独跑。
检出位置从插件包目录向上两级找到仓库根。测试或非 link 安装可以用环境变量 `DSH_SLEUTH_KB_ROOT` 指定；
插件包不在仓库内（快照安装）且没有该变量时，检查静默停用。

- 落后时展开态加一行「知识库落后 N 个提交」，带「去同步」「稍后」两个动作。
  收起态胶囊末尾加「· 知识库有更新」。
- 「去同步」打开整页「Ascend Sleuth」，并尽力切到「知识库」子页。
  同步由那一页的「立即同步」执行，状态条不自己合并。
- 「稍后」记下这一版远端提交：同一提交不再提示，远端有新提交时重新出现。
  记录写主检出的 `.local/kb-sync-notify.json`（落在主检出里，不进 git，不放 `traces/`）。
  写不进去时提示行不收起，并说明是状态文件没写成。
- 待同步的改动含面板代码（`dsh-plugins/` 下有改动）时补一句
  「这批改动含面板代码：同步后重启 DSH 才能加载新面板。」；只提示，不自动重启进程。
- 静默条件分两种后果：
  - 清掉已显示的提示：`sync.enabled` 关闭（主检出 `.local/settings.json` 里的 `sync.enabled`）、
    离线部署、远端已经没有落后（`behind = 0`）。
  - 保留已显示的提示、等下一次成功检查再更新：网络或凭据失败。失败不上屏、不弹窗（首版不做系统通知），
    失败原因在能写状态文件时落到那里供排查。
- 检出里没有 `scripts/kb_sync.py` 时检查停用；此时已经显示的提示要等到进程重启才消失。
- 当前会话工作区不是检出时状态条本身不显示；后台检查仍按主检出跑。

### 诊断总览

工具条入口或状态条标题打开。两栏：左列是全库诊断（按最近更新排），右列是选中单的详情与动作。

- 搜索：左列顶部输入框按单号、summary、命中 case、排除项、平台 / 框架、证据路径过滤；按 `/` 聚焦，`Esc` 清空。
- 命令面板：`⌘K` / `Ctrl+K` 打开，输入过滤命令，`↑` `↓` 选择、`Enter` 执行；命令覆盖主操作、复制结论 / issue 文本、看报告、查上游、回报、沉淀、步骤时间线、刷新与关闭。
- 只读档位：「标记已合入」「手动改状态」禁用并给原因，这两项写 PR 台账。
- 只读档位：「保存 PR 目标」禁用并给原因，这一项写本地配置。
- 只读档位：单条与批次的查合入都回落到生成查证指令。
- 筛选：左列搜索框下方，分为全部 / 进行中 / 待回报 / 可沉淀，带计数；筛选选择同样记住。诊断与沉淀两个视图共用这处筛选，切换视图后位置不变。
- 批量沉淀：筛选切到「可沉淀」时，左列顶部出现批次条，范围 = 当前筛选（含搜索词）；点开先在弹层预览
  一条 `to-postmortem` 批量指令（带 session 列表，并要求先跑只读的 `scripts/sediment_batch.py --json` 核对分组），
  再选择复制或填入输入框。指令里写明只写 `sedimented`、不改 `status` / `feedback.outcome`。
- 键盘：`↑` `↓` 选择（选中行会滚进可视区），`Enter` 触发主操作（焦点在行按钮上同样生效），`Esc` 关闭，`Tab` 在浮层内环绕；
  打开浮层前的焦点在关闭后归还。主操作会把指令填进输入框并关闭浮层。
- 取数失败：给原因与「重试」，不再停在骨架屏；首屏成功过以后轮询失败会保留旧数据并标「数据可能过期」，
  不把过期数据显示成实时状态。
- 选中项按单号记住：10 秒刷新导致列表重排后仍停在同一条单上，不会静默换单。
- 左列每行：状态点、案例一句话、状态 / 平台 / 框架 / 更新时间、第 N/6 步。
- 右列顶部是识别行：一行放状态徽标、身份标签（如命中 case、知识库未覆盖、待回报、已排除条数；最多 3 个）、第 N/6 步与更新时间。
- 识别行下面是问题背景：整段 `summary` 按正文排版，默认收四行，更长的另给「展开全文」。路径、错误码、函数调用按等宽显示。
- 再往下是一条「在等」窄行；接近收尾时出现**收尾清单**；命中 case 时出现**上游查证**块；**证据与沉淀**块；
  **写入历史**；进度、平台、命中 case、已排除、沉淀、反馈、报告等字段；底部常驻动作条
  （主操作、复制摘要、更多操作）。复制续接指令、固定到状态条、切到该诊断的会话等动作在「更多操作」里。
- 更多操作按组排列：生成指令（续接 / 查 case 上游状态 / 定位报告 / 交接包）、回报与沉淀
  （回报结果 / 沉淀为 case / 升格草稿 / 复核回报）、改状态（收尾 / 重开 / 沉淀状态；终态单另给
  「改收尾方式」与「补记收尾方式」，目标与字段来自 `_trace_state.py` 的 actions，不在界面重算状态机）、
  复制（摘要 / issue 文本 / 续接指令）、导航（固定到状态条 / 刷新 / 诊断总览 / 切到该诊断的会话，
  原始会话与最近续接会话都可切）。

### 工作区门禁与会话归属

- **只在 ascend-sleuth 工作区出现**：Host 半从会话工作区 cwd 往上找 `scripts/_trace_state.py`；找不到、或取不到 cwd 时返回 `E_NO_ROOT`，浏览器半不渲染。别的工作区里插件装在 profile 里但状态条不显示。
- **会话归属**：总览详情显示「原始会话」（顶层 `harness_session`）与「续接会话」（每个 `resume` 事件里的 `harness_session`），当前会话带「当前会话」标记；可切到原始会话或最近续接会话。跨机交接或旧环境的会话可能切不过去，界面只提示一句原因，归属仍保留。
- **没记会话号**：顶层 `harness_session` 为空时显示提示与可复制的补写命令
  `python3 scripts/link_harness_sessions.py --trace <文件名> --session-id "$DSH_SESSION_ID" --apply`。
- **续接不改归属**：续接只在 `resume` 事件里写当前会话号，顶层 `harness_session` 保持原始值，继续用于成本 / 工具调用归因；状态条在续接会话里标「本会话（续接）」。

### 详情分块：收尾清单、上游、证据与历史

- **收尾清单**：诊断进入收尾（已定位 / 待回报 / 可沉淀 / 已交草稿）后出现，四项各有完成态与一键入口：
  人读报告（未产出时生成报告指令）、回报结果（待回报时打开回报表单）、沉淀（还没沉淀且有内容时生成沉淀指令）、
  交接包（可随时导出）。完成态全部从现有 trace 字段读，不新增判断。
- **上游查证**：命中 case 后显示锚点（repo#issue / pr）、`validation_record.last_verified` 与依据、
  本机 `gh` 就绪状态；「查 case 上游状态」生成的 prompt 会带上这些锚点与上次查证时间，agent 不必再猜。
- **证据与沉淀**：列出 trace 里记过的证据文件路径（可复制）；列出 `sediment_candidates`，按 kind（case / reference / triage）生成对应沉淀指令；没有候选的单也能从「更多操作」起沉淀，菜单项注明「未标候选，按 trace 起草」；有 `traces/<单号>.report.md` 时点「看报告」在面板内展开原文（只读，512 KiB 上限）。
- **在等材料**：`waitingOn: user_material` 或 trace 里记了缺失材料时出现；把 `evidence_missing` 里的
  「缺 / 未提供」项拆成清单（不补猜），同时列出已有证据；可「复制清单」或带清单「填入续接指令」。
- **步骤时间线**：按需懒加载单条 trace 的事件（用户 / 助手 / 续接、step 与动作、输出、判断依据、证据文件），
  不用离开总览去翻 YAML。
- **写入历史**：状态转移、回报、复核合成一条时间线；当前已是终态且最后一条转移是收尾时，给
  「撤销上次收尾」（重新打开；只清掉收尾方式 `ending`，收尾时间与停止原因保留。写入走同一条 `trace_transition.py` 与 CAS）。

### 一键指令：填入输入框前先给预览

动作菜单按用途分组，生成的都是完整指令（对象、动作、字段、来源写全）。指令里的 skill 用 DSH Web 的
`/name` 形式（如 `/diagnose`、`/to-postmortem`），由宿主识别并注入 skill 正文；`/skill:name` 是旧 TUI 的写法，DSH Web 不识别。

- **生成指令**：续接诊断 / 贴材料继续、**查 case 上游状态**、产出或修订人读定位报告、
  导出交接包（另一台机器接手）。查上游不靠插件发网络请求：先在菜单里显示本机 gh 是否可用（与
  `scripts/doctor.py` 的 gh 检查同一件事），再生成一份带环境预检的 prompt，让 agent 用
  `scripts/verify_upstream_outcomes.py --case <id> --dry-run/--apply` 幂等落账（同一结局不重复累加）。
- **回报与沉淀**：**回报结果…**（表单：结果 / 来源 / 备注，带指令预览）、沉淀为 case、升格草稿、复核回报。
- **改状态**：收尾（已定位 / 转交 / 不再跟进）、重新打开、沉淀状态。收尾表单带「问题背景」（收尾时写入 trace 顶层
  `summary`，缺它会写不进去）与严重级；`fixEmitted` 的初值取 trace 现有记录。已收尾的单不再给这三项，
  只给重新打开、改收尾方式、补记收尾方式与沉淀状态：终态单再点收尾会被脚本当成「改收尾方式」，静默重写收尾记录。
- **复制**：结论摘要（可直接粘进群聊）；「复制为 issue 文本」按「标题 / 现象 / 环境 / 相关 case /
  证据 /（已收尾时）结论 / 单号」排成纯文本，内容只抄 trace 已有事实，进行中的内部待办不外发。
- **导航**：诊断总览、刷新、切到该诊断的会话。

「回报结果」不再是一句模糊的「确认是否解决」：表单收来源（现场验证 / 厂商答复）、结果（4 档）与备注，
下方实时预览将填入输入框的完整指令，提交后才写回输入框。回报轴目前没有脚本写入口，所以这一步仍是
生成指令、由 agent 按 trace 写入纪律落盘；表单会把要写的 report 事件字段与 `feedback.outcome` 取值写清。

### 沉淀队列（v1）

诊断总览顶部加了「诊断 / 沉淀」切换。沉淀视图把 `postmortems/inbox/` 的草稿按下一步分组（继续 groom /
待提 PR / 待合入与收尾），顶部批次条给整批的下一步；右列是单份草稿的五步进度（草稿已交 → 已评估 →
已决定 → 已提 PR → 已升格）、评估、人决定、落点与 PR。状态条展开态多一行沉淀摘要，收起态不变。

- 数据：`copilot-sediment` → `lib/sediment_state.py`，复用 `scripts/groom_status.py` 与
  `scripts/groom_common.py` 的判据，不复制；只读，按需读（展开状态条或打开沉淀视图时），不塞进 10 秒轮询。
  填过任一指令后重新打开队列会强制刷新一次；平时 60 秒内复用上次结果。
- 右列顶部与诊断详情一致：一行识别信息（阶段、评估建议、来源诊断、天数），下面按正文排草稿标题
  （标题取自草稿 case 的 `title`，没有 case 时取 postmortem 首行），长标题给「展开全文」。
  来源诊断显示 trace 单号，点它切到该 trace 记的会话（`harness_session`）。trace 没记会话号时
  该项不可点，悬停给原因；单号与会话号不是同一个值，用单号去开会话会报 `unknown session`。
- 推送目标：第一次生成提 PR 指令时选一次远端与 base 分支，存在主检出的 `.local/settings.json`
  （旧版本读 `.groom/pr-state.json` 的 `target` 段，保留兼容），之后复用。选择器只列事实（host、平台、
  分支、适配器/token 状态），不预设远端用途；没有目标时先选，不默认猜。已有 PR 的行不显示这句，
  避免被读成「没有 PR」。
- PR 状态：台账记平台、repo、号、URL、状态与查证来源/时间。批次条「查全部合入状态」跑
  `pr_status.py --check-all --json-lines`。详情里的「查合入状态」跑单条 `--check`，几秒内回写台账。
- 查合入逐条进度：整批查时批次条显示「查合入中 n/m」，n 是已查完条数，m 是台账里待查条数。
  每查完一条，这一行的状态或失败原因立即出现在行里，不等整批。
  结束时刷新为台账快照（含「上次查证」）。
- 查合入的结果：成功与失败都给提示，单条给出 PR 号与新状态，整批给出更新条数，失败给出原因。
  没有写权限时单条与批次都回落到生成查证指令；没有适配器或 token 时提示原因，不假装查过。
  查不到就写「未确认」，不推成「已合入」。
- 查合入写台账被系统拒绝时（文件只读、访问控制、被别的进程占用），打开指令弹层：交代原因、查到的状态、
  对应 `pr_status.py` 命令、写的是哪份文件与命令也失败时的排查步骤；点「填入输入框」交给会话里的 agent
  执行，不会自动发送。查询类失败（没适配器、没 token）与读坏台账仍只给原因，不生成指令。
- 人工兜底：平台一直查不到时，详情里的「手动改状态」按人确认写 PR 台账。四档是待合入 / 已合入 /
  已关闭 / 未确认，对应 `pr_status.py --mark`，来源记为「手动确认」。下一次查合入仍以平台结果为准。
  手动改状态与查合入写同一份台账，写不进时同样给指令，不让人对着不可写的文件重试。
- 队列跟到合入：草稿移进 `.done/` 之后，只要台账里 PR 还没走完，就仍以一行留在「待合入与收尾」。
  标题与决定从 `.done/` 与 close-log 读，PR 从台账读；已出队的行在详情里注明来源。PR 合入并收尾后
  进「最近完成」，历史行带 PR 链接。PR 被关闭时主按钮是「恢复草稿」，点击把移动命令填进输入框。
- 撤销沉淀：草稿还在 inbox、PR 没提过或已关闭、来源 trace 也没说升格时，详情动作行给「撤销沉淀」。
  点开是一条指令：`scripts/sediment_undo.py --draft-key <key>` 先打印计划，加 `--apply` 才执行。
  面板不删草稿；点「填入输入框」交给会话里的 agent。撤销还原沉淀状态，PR 已关闭时一并清掉本地台账记录；
  诊断状态不改；要回到进行中，在诊断面板用「重新打开」。
- 批量撤销：批次条在可撤销的行有 2 份及以上时给「撤销可撤销的 n 份」，范围 = 当前列表（筛选与搜索词）。
  点开预览一条带多份 `--draft-key` 的指令（含本批名单）；填入后从两条命令里各删掉不想撤的
  `--draft-key`，再由 agent 逐份执行。
- 撤销脚本的动作：
  - 草稿移进 `postmortems/inbox/.undone/`（移回即复活）；
  - 删掉评估状态文件（`.groom/assessments/<key>.yaml`）；
  - 来源 trace 的 `sedimented` 改回 `none`（trace 缺失或外部来源时跳过）；
  - PR 记录是「已关闭」时，清掉台账里那条记录（PR 的编号与地址写进 undo-log 与 `.undone/` 里的 `.undo.json`）。
  撤销成功后另写一行 `.groom/undo-log.jsonl`（评估 id、人决定、草稿去向与 PR 的编号与地址）。
  诊断状态（`resolved` / `in_progress` 等）保持不变，撤销不会把已收尾的单重新打开。
- PR 没关闭（`open` / `unknown`）或已合入（`merged`）的草稿拒绝撤销：PR 是外部事实，先在平台上处理它。
  已关闭的记录不再拦撤销；单独清一条已关闭记录用 `python3 scripts/pr_status.py --root . --forget --draft <key>`
  （只允许 `closed`，写前比对台账文件字节防并发覆盖）。trace 已说升格的草稿也拒绝撤销；已出队的用「恢复草稿」。
  `.undone/` 没有保留期，确认不再需要后手工删。
- 平台适配器：`scripts/platforms/` 下一个 YAML（标准 REST）或一个 Python（CLI/特殊认证）；新增平台
  只加一个文件，核心与界面不改。doctor 从清单里查 token 与命令，缺项降级，不代装。
- 指令：默认短指令（目标、批次、边界、台账写点），命令细节折叠；流程在
  `/knowledge-groom`，界面不抄第二份。
- 写：目标选择写主检出的 `.local/settings.json`；查合入与手动改状态写 PR 台账（两者都带 CAS）。
- 写：状态转移走 `trace_transition.py`。提 PR、收尾仍由 agent 执行生成的指令，不改 `knowledge/` 与 `traces/`。

## 数据与写入链路

```
浏览器半（lib/client.js）
  ├─ copilot-state      → Host 半 → lib/copilot_state.py → scripts/_trace_state.py（状态判据）
  ├─ copilot-sediment   → Host 半 → lib/sediment_state.py → scripts/groom_status.py / groom_common.py
  ├─ copilot-pr-target  → Host 半 → scripts/pr_status.py → scripts/platforms/*
  ├─ copilot-transition → Host 半 → scripts/trace_transition.py（校验 + CAS + 事件）
  └─ copilot-kb-dismiss / copilot-kb-recheck → Host 半 → scripts/kb_sync.py（知识库落后检查；
       周期检查另由 Host 半定时触发，结果随 copilot-state 的 kbNotice 下发）
```

- 读：状态名、动作可用性、「在等什么」全部来自 `scripts/_trace_state.py` 的投影（Host 半经 `lib/copilot_state.py` 调用），浏览器不判状态。
- 写：一律经 `scripts/trace_transition.py`，带内容指纹（trace 原始字节的 sha256）做 CAS；
  并发改动会被拦下并提示刷新。表单打开时冻结指纹，菜单开着期间外部改了 trace 会报冲突，不用屏幕上的旧值覆盖。
- 落点：Host 半不再信任客户端给的 `tracesDir`。只接受「会话检出自己的 `traces/`」或「worktree 会话落到主检出的 `traces/`」，
  realpath 后比对；读报告允许 `traces/` 下子目录，但同样做 realpath 包含校验。
- 能力位：Host 半按当前会话的沙箱档位判定；只读档位下写入项禁用并给出原因。
  读、写脚本的子进程都跟随会话档位：完全权限原样下传，其余档位收窄成 `workspace-write` + 落点检出根并带上会话号；
  解析不出档位时按只读拒绝写。子进程超时 / 被沙箱拒绝 / 输出截断各有专码，不再一律报成「没有返回 JSON」。
- 写入被系统拒绝时，面板给一条现成指令（`生成指令（填入输入框）`），由会话里的 agent 用同一脚本代写；点了才填进输入框，不自动发送。
  覆盖写状态、查合入 / 手动改状态写 PR 台账、写推送目标三类写点；脚本先把它折成带路径与系统原因的错误码
  （写台账 / 写配置为 `E_LEDGER` / `E_SETTINGS`，带 `write_failed` 标记；沙箱或档位拒绝为 `E_PERM`），面板再按错误码给指令
  （写台账与写配置分别指向各自的文件与 `.lock`，沙箱拒绝再说明这是权限模式判断）。
- 浏览器半不解析 YAML，也不直接写文件。传给脚本的参数写临时 JSON 文件（权限 0600，成功失败都清理），
  不把含空格、引号与中文的值拼进命令行。

## 写状态的边界

可写：收尾（已定位 / 转交他人 / 不再跟进）、重新打开、沉淀状态（未沉淀 / 已交草稿 / 已升格 / 已归档）。

**不可写：现场回报结果（feedback.outcome）**。当前 `scripts/trace_transition.py` 的
`--field outcome` 尚未开放，而 `--field report` 在对已有 `feedback` 块的 trace 上会因写后校验失败回滚
（`reports` / `feedback` 不在脚本的 `TOUCHED` 集合里）。所以「回报结果」这一组只生成指令，
由 agent 按现有 trace 写入纪律落盘。等脚本补上写入口后，这里可以换成直接写。

## 安装与卸载

它默认和面板一起装：`node scripts/panel_install.js --all` 会依次装面板包、vllm-kb 与它；路由三/四/五
的细节见 `skills/preload-panel/SKILL.md`。只想单独装它时用 `--spec` 或插件页粘贴本目录。

装进当前 profile：

```
plugin_manager install_bundle(target: '<仓库绝对路径>/dsh-plugins/dsh-sleuth-copilot')
```

或使用安装目录自带的命令行（link 安装，改源码后不必重装）：

```
<安装目录>/runtime/cli/bin/dsh plugin --profile <profile> add "<仓库绝对路径>/dsh-plugins/dsh-sleuth-copilot"
```

卸载：

```
plugin_manager remove_bundle(target: 'dsh-sleuth-copilot')
```

装完要重启宿主进程（Host 半的路由在进程启动时注册），刷新页面加载浏览器半。

## 与既有面板的关系

两者共用同一份状态判据（`scripts/_trace_state.py`），入口不同：

| 界面 | 读者的问题 | 位置 |
|---|---|---|
| 诊断 tab / 整页「Ascend Sleuth」 | 这一单 / 全库现在是什么样 | 切过去看 |
| 诊断状态条（本包） | 现在该做什么、顺手改状态 | 输入区，一直在 |

面板适合复盘与全库读数；本包适合诊断进行中的那几十分钟。两者都装不冲突，卸载本包不影响面板。
