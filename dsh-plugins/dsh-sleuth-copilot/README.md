# 诊断状态条（dsh-sleuth-copilot）

DSH 会话里的一个独立交互层插件。它把诊断的状态、下一步动作与知识沉淀入口放进对话本身，
不改现有面板源码，可单独安装、单独卸载。

四个面共用一份数据与一套偏好：

| 面 | 位置 | 用途 |
|---|---|---|
| 状态条 | 输入框上方（`conversation.input.dock`） | 本会话诊断到第几步、在等什么、下一步做什么；可收起，收起状态记住 |
| 工具条入口 | 输入框右侧工具条（`conversation.input.right`） | 打开诊断总览；有待回报时带角标 |
| 诊断总览 | 全帧浮层（`shell.overlay`） | 全库诊断一屏看完、键盘操作、复制指令、直接改状态 |
| 动作层 | 以上三个面共用 | 复制结论摘要与各类指令；收尾 / 重开 / 沉淀状态写入 |

## 为什么是这个形态

现有四类界面（诊断 tab、整页「Ascend Sleuth」、诊断记录浮层、侧栏行标记）都要先切过去才能看。
诊断本身发生在对话里：贴日志、判候选、再问一个缺口，状态与动作应当跟着对话走。

三个判断决定了现在的形态：

1. **状态条默认收起成窄胶囊、可展开、记住上次选择**。读者常要盯消息，信息块不能一直挡着输入区。
2. **下一步只有一个主按钮**，其余动作收进「更多操作」。多个平级按钮等于让读者每次重新判断。
3. **全库视图是浮层，不是新页面**。需要横向比较多单时打开，看完 Esc 关掉，不离开当前会话。

## 界面与交互

### 状态条

- 一行人物：状态点、范围（本会话 / 最近一单）、**人读的案例一句话**、状态徽标、主按钮、更多操作、收起。
  案例标题取自 trace 的 `summary` 第一句，诊断单号不进标题；鼠标悬停看全文，点标题直接打开总览到这一单。
- 一行元信息：六段进度轨与第 N/6 步、平台 / 框架 / 性质、在等什么、身份标签（命中 case / 知识库未覆盖 /
  待回报 / 可沉淀 / 已排除几条）。
- 收起态（默认）：输入框上方居中的一个窄胶囊（自动宽度，不占满一行）：状态点 + 案例标题 + 第 N/6 步
  +（欠回报时）「待回报」，点击展开成完整状态条，再点收起。静置约 2.8 秒后淡到 34%，鼠标移动、页面滚动或聚焦输入框时回到不透明；
  `prefers-reduced-motion` 下不淡出。收起选择写进 `localStorage` 的 `dsh-sleuth-copilot.prefs.v2`，下次打开保持。
- 欠回报时状态点变琥珀色；诊断步骤前进（同一单第 N 步变大）时状态点轻闪一次，不改变高度与位置。
- `⌘⇧D` / `Ctrl+Shift+D` 在会话界面（状态条挂载的输入区）打开诊断总览，并选中当前跟踪的那一单；整页与设置页没有状态条，不响应。
- 手动选单：点左端范围标签（本会话 / 最近一单 / 已固定）打开选择器，可搜索并把状态条固定到任意一单；
  「跟随会话」恢复自动。固定按会话记住。
- 本会话有绑定轨迹（轨迹的 `harness_session` 等于当前会话号）时标「本会话」；没有时兜底显示
  「最近一单」，并给出续接指令。
- 工作区不是 ascend-sleuth 检出时整条不渲染；检出内缺 Python 或脚本出错时给一行原因与重试。

### 诊断总览

工具条入口或状态条标题打开。两栏：左列是全库诊断（按最近更新排），右列是选中单的详情与动作。

- 筛选：顶部分段控件，全部 / 进行中 / 待回报 / 可沉淀，带计数；筛选选择同样记住。
- 键盘：`↑` `↓` 选择，`Enter` 触发主操作，`Esc` 关闭；主操作会把指令填进输入框并关闭浮层。
- 左列每行：状态点、案例一句话、状态 / 平台 / 框架 / 更新时间、第 N/6 步。
- 右列：案例标题与状态徽标；「现在在等」的高亮区块；接近收尾时出现**收尾清单**；命中 case 时出现
  **上游查证**块；**证据与沉淀**块；**写入历史**；进度、平台、命中 case、已排除、沉淀、反馈、报告等
  字段；可展开的摘要；底部动作行（主操作、复制摘要、复制续接、更多操作）。
- 更多操作里是完整动作组：复制（摘要 / 续接 / 沉淀 / 升格 / 回报）、回报结果（生成指令）、
  收尾（已定位 / 转交 / 不再跟进）、重开、沉淀状态、刷新、诊断总览、切到该诊断的会话。

### 详情分块：收尾清单、上游、证据与历史

- **收尾清单**：诊断进入收尾（已定位 / 待回报 / 可沉淀 / 已交草稿）后出现，四项各有完成态与一键入口：
  人读报告（未产出时生成报告指令）、回报结果（待回报时打开回报表单）、沉淀（可沉淀时生成沉淀指令）、
  交接包（可随时导出）。完成态全部从现有 trace 字段读，不新增判断。
- **上游查证**：命中 case 后显示锚点（repo#issue / pr）、`validation_record.last_verified` 与依据、
  本机 `gh` 就绪状态；「查 case 上游状态」生成的 prompt 会带上这些锚点与上次查证时间，agent 不必再猜。
- **证据与沉淀**：列出 trace 里记过的证据文件路径（可复制）；列出 `sediment_candidates`，按 kind（case / reference / triage）生成对应沉淀指令；有 `traces/<单号>.report.md` 时点「看报告」在面板内展开原文（只读，512 KiB 上限）。
- **写入历史**：状态转移、回报、复核合成一条时间线；当前已是终态且最后一条转移是收尾时，给
  「撤销上次收尾」（重新打开；只清掉收尾方式 `ending`，收尾时间与停止原因保留。写入走同一条 `trace_transition.py` 与 CAS）。

### 一键指令：填入输入框前先给预览

动作菜单按用途分组，生成的都是完整指令（对象、动作、字段、来源写全）：

- **生成指令**：续接诊断 / 贴材料继续、**查 case 上游状态**、产出或修订人读定位报告、
  导出交接包（另一台机器接手）。查上游不靠插件发网络请求：先在菜单里显示本机 gh 是否可用（与
  `scripts/doctor.py` 的 gh 检查同一件事），再生成一份带环境预检的 prompt，让 agent 用
  `scripts/verify_upstream_outcomes.py --case <id> --dry-run/--apply` 幂等落账（同一结局不重复累加）。
- **回报与沉淀**：**回报结果…**（表单：结果 / 来源 / 备注，带指令预览）、沉淀为 case、升格草稿、复核回报。
- **改状态**：收尾（已定位 / 转交 / 不再跟进）、重新打开、沉淀状态。
- **复制**：结论摘要（可直接粘进 issue 或群聊）。
- **导航**：诊断总览、刷新、切到该诊断的会话。

「回报结果」不再是一句模糊的「确认是否解决」：表单收来源（现场验证 / 厂商答复）、结果（4 档）与备注，
下方实时预览将填入输入框的完整指令，提交后才写回输入框。回报轴目前没有脚本写入口，所以这一步仍是
生成指令、由 agent 按 trace 写入纪律落盘；表单会把要写的 report 事件字段与 `feedback.outcome` 取值写清。

## 数据与写入链路

```
浏览器半（lib/client.js）
  ├─ copilot-state      → Host 半 → lib/copilot_state.py → scripts/_trace_state.py（状态判据）
  └─ copilot-transition → Host 半 → scripts/trace_transition.py（校验 + CAS + 事件）
```

- 读：状态名、动作可用性、「在等什么」全部来自 `scripts/_trace_state.py` 的投影（Host 半经 `lib/copilot_state.py` 调用），浏览器不判状态。
- 写：一律经 `scripts/trace_transition.py`，带内容指纹（trace 原始字节的 sha256）做 CAS；
  并发改动会被拦下并提示刷新。
- 能力位：Host 半按当前会话的沙箱档位判定；只读档位下写入项禁用并给出原因。
- 浏览器半不解析 YAML，也不直接写文件。

## 写状态的边界

可写：收尾（已定位 / 转交他人 / 不再跟进）、重新打开、沉淀状态（未沉淀 / 已交草稿 / 已升格 / 已归档）。

**不可写：现场回报结果（feedback.outcome）**。当前 `scripts/trace_transition.py` 的
`--field outcome` 尚未开放，而 `--field report` 在对已有 `feedback` 块的 trace 上会因写后校验失败回滚
（`reports` / `feedback` 不在脚本的 `TOUCHED` 集合里）。所以「回报结果」这一组只生成指令，
由 agent 按现有 trace 写入纪律落盘。等脚本补上写入口后，这里可以换成直接写。

## 安装与卸载

它默认和面板一起装：`node scripts/panel_install.js --all` 会依次装面板包、vllm-kb 与它；路由三/四/五
的细节见 `skills/preload-panel/SKILL.md`。只想单独装它时用 `--spec` 或插件页粘贴本目录。

装进当前 profile：

```
plugin_manager install_bundle(target: '<仓库绝对路径>/dsh-plugins/dsh-sleuth-copilot')
```

或使用安装目录自带的命令行（link 安装，改源码后不必重装）：

```
<安装目录>/runtime/cli/bin/dsh plugin --profile <profile> add "<仓库绝对路径>/dsh-plugins/dsh-sleuth-copilot"
```

卸载：

```
plugin_manager remove_bundle(target: 'dsh-sleuth-copilot')
```

装完要重启宿主进程（Host 半的路由在进程启动时注册），刷新页面加载浏览器半。

## 验证

```
node dsh-plugins/dsh-sleuth-copilot/test/render-smoke.mjs   # 浏览器半：四个面、折叠持久化、收尾清单 / 历史 / 报告、总览键盘与 ⌘⇧D
node dsh-plugins/dsh-sleuth-copilot/test/host-smoke.mjs     # Host 半：取数、证据 / 候选、报告只读读取、真实写入（临时副本）、CAS、错误码
```

页面上的三件事只能人工确认：状态条是否出现、排版是否贴合输入区、点按钮是否把指令写进输入框。
装完刷新页面，在状态条展开页或控制台看版本串 `v0.8.0`。

## 版本维护

`package.json` 的 `version` 与 `lib/client.js` 的 `PLUGIN_VERSION` 一起改；页面版本串来自后者。
快照安装按版本号判新旧，不递增不会换装。

## 与既有面板的关系

两者共用同一份状态判据（`scripts/_trace_state.py`），入口不同：

| 界面 | 读者的问题 | 位置 |
|---|---|---|
| 诊断 tab / 整页「Ascend Sleuth」 | 这一单 / 全库现在是什么样 | 切过去看 |
| 诊断状态条（本包） | 现在该做什么、顺手改状态 | 输入区，一直在 |

面板适合复盘与全库读数；本包适合诊断进行中的那几十分钟。两者都装不冲突，卸载本包不影响面板。
