# 诊断总览与沉淀队列的多选：选择集、批量动作与两级撤销

状态：已实现（面板包 0.23.1），待评审
范围：`dsh-plugins/dsh-sleuth-copilot` 的两处左列（诊断总览、沉淀队列）、两处批次条与指令弹层。不改队列分组与下一步判定，不改 `trace_transition.py` 与 `sediment_state.py` 的判定逻辑。
读者：评审这次交互的人、后续维护面板的人。

## 1 要解决什么问题

### 1.1 批量撤销只能整批

沉淀面板的批量撤销，范围是「当前列表（筛选与搜索词）」。要撤 8 份里的 3 份，读者点开它，得到两条各带 8 个 `--draft-key` 的命令，再手工删掉 5 个参数。README 的「批量撤销」一节写的就是这条操作路径。

8 份的 `--draft-key` 串约 400 字符。删 5 处没有校验；删错一个参数，脚本照常执行，只是撤的不是读者以为的那几份。

### 1.2 批量沉淀只能整批

诊断侧的批量沉淀只在「可沉淀」筛选下出现，范围是整个筛选（含搜索词）。要沉淀 12 单里的 3 单，只有两条路：改搜索词把列表缩到 3 单，或者逐单打开菜单。

改搜索词之后，别的单看不到了。批次条的条数也从 12 变成 3，读者分不清这是「选了 3 单」还是「库里只剩 3 单」。

### 1.3 动作做错没有回执

面板自己写台账的两处能回退（PR 状态、收尾），生成指令的动作没有回执。动作回执是记下这次对谁做了什么、走到哪一步的窄条。

填入指令后面板立即关闭。读者回到会话里，面对一段几十行的文本，既没有「这批是哪几单」的记录，也没有撤回入口。

### 1.4 共同的原因

三处都指向同一件事：动作范围只能由筛选定义。筛选回答「看什么」，动作范围回答「对谁做」，两者绑在一起，读者要改动作就得先改视图。

## 2 选哪条路

### 2.1 选择集常驻，动作范围分两层

选丙：行前留一个复选框槽位，默认不画框，悬停、键盘焦点或进入选择后露出；加一个选择集（用稳定 id 记住的一组行），动作范围分「所选」与「整批」（当前筛选里这一批的动作对象）两层。另两条是甲与乙：

- 甲：只给指令弹层加「逐条移除」。改动最小，但读者仍要先把筛选调对；跨筛选凑不出一批；诊断侧根本没有批次可改。
- 乙：加「多选模式」开关。进入后点行就是勾选，主操作变批量。省一个复选框，但「点行看详情」在模式里失效，`Enter` 的语义跟着变，读者还要记住当前在哪个模式。

选丙放弃的是列表的一点左侧宽度与 DOM 结构：每行左端多一个 24px 槽位（默认不画框），行内容从一个按钮变成两个并列控件。换来的是首屏干净、批次条能写出「这批是谁」；触屏没有悬停，所以另给「选择」入口。

### 2.2 撤销按面板能看见的状态分三档

撤销分两级：选择集本身可以撤销，动作也能撤销。两级的成立条件不同，动作这一级按面板能看见的状态分三档，不把「已填入」当「已执行」。

- 未填入：关掉弹层就是撤销，不留回执。
- 已填入未发送：回执写「已填入输入框，尚未发送」，给「清空输入框」与「复制名单」。清空前要二次确认：面板只经 `setDraft` 写输入框，读不到里面的内容，判断不了文本是否仍是本批原文。
- 已确认写入：面板自己写台账的动作（标已合入、手动改状态），立即反写旧值，走现有内容指纹校验。冲突时提示刷新，不覆盖。

选择这一级不碰写入，按步退回即可，最多 5 步（见 3.6）。

被否决的两条路：只做选择态撤销，动作本身错了仍然没有退路；生成指令的动作统一给反向指令并写「已撤销」，不成立，面板只生成文本，不知道 agent 是否执行。

依据是《设计原则》第七条「变更可逆」与第十条「诚实退化，永不假装」（`docs/spec/design-principles.md` §3）。

### 2.3 不做什么

- 不做批量收尾、批量改状态：每单要填 `severity`、`fix_emitted`、`summary`，批量会静默覆盖。`DESIGN.md` 的「收尾表单只对进行中的单给」一节记过这个坑。
- 不做框选，不做 Vim 风格的移动键。
- 不做跨视图共享选择：诊断行与沉淀行的 id 不在一个域里，混在一起批量动作没有意义。
- 不做选择持久化：列表会随轮询刷新，隔天恢复一批「已选」而行早已变状态。
- 不做全库全选，只做「全选当前筛选」。

## 3 交互规格

### 3.1 两个概念

选择集是一组成员，用稳定 id 记（诊断视图用 `sessionId`，沉淀视图用草稿 key）。刷新、重排、切筛选都不改它，只按 id 重新对应行。

焦点行是右列详情正在显示的那一行。它与选择集互不代替：焦点可以停在 A，选择集里是 B、C、D；焦点也可以不在选择集里。

### 3.2 选择怎么进入

鼠标与键盘都能改选择；点行内容仍然是看详情，与现在一致。复选框默认不显示：悬停该行、键盘焦点落到该行，或点筛选行右侧的「选择」后露出，有勾选时保持露出。

- 点复选框：切换这一行的选择，焦点不动。
- `Shift` + 点复选框：从上次点的行到这一行，当前可见的行一起加入或移出。
- `Cmd` / `Ctrl` + 点行内容：切换选择，焦点跟到这一行。
- `Shift` + 点行内容：扩展选择，焦点跟到这一行。
- 空格：切换焦点行的选择。
- `Cmd` / `Ctrl` + `A`：全选当前筛选（含搜索词）。已有选择时替换，不合并；焦点在输入框里时不接管。
- `Esc`：选择集非空时清空，并留一步可撤销；选择集为空时才关面板。

复选框是行外的独立按钮（`role="checkbox"`、`aria-checked`），不嵌在行按钮里，也不占 `Tab` 停靠点（`tabIndex=-1`）：鼠标点它改选择，键盘用空格切换焦点行的选择。行仍是按钮，`Enter` 与双击语义不变；选择变化时读屏播报「已选 3 项」。

### 3.3 选择集与范围

批次条同时是列表表头，它的文案决定动作作用在谁身上。

| 状态 | 左侧 | 右侧 |
|---|---|---|
| 未选 | 全选复选框 + 现有整批摘要（条数、分组、最久天数） | 现有整批动作 |
| 已选 | 全选复选框（半选态）+「已选 3 项 · 当前筛选 12 项」或「已选 3 项 · 其中 1 项不在当前筛选」 | 主操作 + 更多 + 清空 |
| 有失效项 | 追加「1 项已不在队列」 | 「移除失效项」 |

主操作按所选行的状态取：

- 诊断视图：所选全都能起沉淀，主操作是「沉淀所选 3 单」。有不能起的，主操作换成「复制所选清单」，沉淀进「更多」，并标「其中 1 单没有可沉淀内容」。
- 沉淀视图：按所选行各自的下一步计数，主操作取条数最多的那一步（并列时按提 PR、查合入、收尾、恢复、groom 的顺序）。按钮文案带动作与条数，例如「提 PR 3 份」「查合入 4 份」。其余动作进「更多」，每项标条数；不可用的动作不出现，不摆一个按不动的按钮。

右列始终显示焦点行，详情里的单条动作也只作用于焦点行，与选择集无关。批次条负责「所选」与「整批」两个范围；它写「已选 3 项」，不暗示右列是第 4 项。

选择集里有行不在当前筛选时，批次条给「只看已选」开关。打开后列表只显示选中行，勾选与焦点照常。

### 3.4 挑选场景

挑选阶段只改选择集，不触发写入。

1. 单条沉淀：点行看详情，菜单里「沉淀为 case」。与现在一致。
2. 整批沉淀：不勾选，任一筛选下当前筛选里有可沉淀的单就出现批次条，主操作「沉淀当前筛选 12 单」（n 为可沉淀单数）。
3. 挑 3 单沉淀：勾 3 行，批次条「已选 3 项 · 当前筛选 12 项」，主操作「沉淀所选 3 单」。
4. 跨筛选凑 3 单：在「可沉淀」勾 2，切「待回报」勾 1，回「可沉淀」。批次条写「已选 3 项 · 其中 1 项不在当前筛选」，并出现「只看已选」。
5. 范围选：点第 2 行复选框，`Shift` 点第 7 行，第 2 到 7 行选中；焦点不动。
6. 全选：点批次条的全选复选框，选中当前筛选 12 项。已选 3 时，文案写「全选当前筛选 12 项（替换已选 3 项）」，点下去是替换。

### 3.5 执行场景

执行前有一次名单确认，名单里可以逐项移除。

7. 沉淀所选：弹层标题「沉淀所选 3 单」，列 3 行（单号 + 标题），每行可移除；移除只改本次名单，不改选择集。主按钮「填入输入框（3 单）」。
8. 撤销所选沉淀：勾 3 份可撤销行，「更多」里「撤销沉淀 2 份」。弹层列 key 与标题，主按钮「填入输入框（2 份）」。名单冻结在打开弹层那一刻，后台刷新不改它。
9. 勾到不可撤销的行：动作只把可撤销的算进条数（勾 3 份里有 1 份已提 PR 就写「撤销沉淀 2 份」）；想少撤哪几份，在列表里取消勾选即可，不必进弹层删。
10. 标记已合入（面板写入）：详情里点「标记已合入」，写入成功后给回执「已标记 #123 已合入 · 撤销」。
11. 手动改状态（面板写入）：同上，回执写明旧状态，撤销写回旧值。

### 3.6 撤销场景

撤销选择随时可用，撤销动作只在面板看得见的状态上成立。

12. 勾错一行：点复选框取消。不占撤销步数。
13. 撤销选择：`Esc` 或「清空」后，选择集清空，批次条回到整批。`Cmd` / `Ctrl` + `Z` 回到清空前的选择集与筛选（含搜索词），最多 5 步。
14. 撤回刚填入的指令：回执写「沉淀所选 3 单 · 已填入输入框，尚未发送」，「清空输入框」二次确认后执行。
15. 复制名单：回执里「复制名单」给本批的 key 与标题，便于贴进工单或在会话里补一句。落盘动作的逆操作不进回执：撤销沉淀的反向要把 `.undone/` 里的草稿移回 inbox，面板现在生成不了这条命令，只能手写 `mv`，要不要加脚本见第 6 节。提 PR 的反向是平台操作，面板给 PR 链接，不生成关 PR 指令。
16. 反写台账：点回执里的「撤销」，把上一状态写回台账。台账被外部改过时提示「台账已变化，先刷新」，不覆盖。
17. 撤销后再撤销：回执变成「已恢复 待合入」，不再给「撤销」。

### 3.7 边界场景

刷新、权限、同 PR、键盘与视图切换，各有各的坏情况要说明。

18. 刷新后行变了：选中行被外部收尾，批次条追加「1 项已变化」，主操作按剩余 2 项重算，并给「移除失效 1 项」。
19. 同 PR 多份：5 份里 3 份同属 #123，批次条标「3 份同属 #123」。查合入仍按 PR 查一次，进度按草稿计。
20. 只读档位：复选框与选择可用，指令照常生成。「标记已合入」「手动改状态」置灰并给原因。
21. 数据过期：轮询失败时批次条标「数据可能过期」，主操作置灰、其余批量动作点了先提示刷新，不按旧范围生成指令；复制仍可用。
22. 切视图：诊断选了 3 单，切沉淀再切回，诊断的选择还在。两个视图各记各的，「撤销选择」只作用于当前视图。
23. 读屏与键盘：行的复选框带 `role="checkbox"` 与 `aria-checked`，鼠标可达、键盘用空格切换焦点行；`Tab` 顺序与原来一致，方向键移动焦点；选择变化时播报「已选 3 项」。

### 3.8 视觉与文案

- 焦点行维持现状：左侧 2px 强调色短标记 + 浅强调底。
- 选中行：复选框勾选 + `surface-2` 行底，不加左标记。焦点与选中同时成立时两者叠加，仍只有一条左标记。
- 批次条主按钮同时写动作与条数，不写「执行」「确定」。
- 回执只写事实：填入了多少、什么时候、是否确认发送。不写「已完成」。
- 三个词不混用：「撤销」用于反写已写入的状态，「清空输入框」用于丢掉刚填入的文本，「复制反向指令」用于生成落盘动作的逆操作。

- `node dsh-plugins/dsh-sleuth-copilot/test/render-smoke.mjs`：现有断言全过；新增断言覆盖场景 1 到 23 里与选择、范围、回执、撤销、失效项、只读档位有关的分支。
- `node scripts/panel_render_check.js`：全过。
- `node scripts/build_panel_bundle.js --check`：面板包产物与源文件一致。
- `node scripts/check_panel_bundle.js`：冒烟通过。
- `python3 scripts/check_panel_tokens.py`：两面板角色集合一致。
- 人工核对：深浅色、900px 以下窄容器、真实鼠标与键盘路径各走一遍。这三项按 `DESIGN.md` 的「验证边界」只能人工确认。

## 5 不做会怎样

- 撤销这一层不可信。读者要手改命令删参数，删错不报错。撤销是队列出错后的回退方式；回退方式本身要先能核对，读者才会在批量上用。
- 诊断侧的批量沉淀只服务「全部都要沉淀」。12 单里沉淀 3 单要走改搜索词的路，改完看不到别的单。
- 没有选择集，以后每个批量动作都只能按筛选定义范围。范围越大越像全库操作，读者会避开批量。

## 6 未决

本节不构成实现依据。

- 撤销沉淀的撤销（把 `.undone/` 移回 inbox）现在只有 `mv` 指令，没有脚本。要不要给 `sediment_undo.py` 加恢复参数，看这类回退的频率。
- 回执保留多久：现在设计成跟随面板打开期间与当前会话。跨会话保留要写 `localStorage`，换机器就看不到。
- 同 PR 多份在撤销时要不要合并成一行显示。
- 诊断视图的「查 case 上游状态」是否也进多选动作，现在只有沉淀与复制清单。
- 选择集要不要按上次使用的筛选恢复，还是每次打开都从空开始。

## 7 依赖与新增的运维工作

- 列表的可访问结构要重排（列表容器声明多选、行承担选择状态与焦点），这是本次最大的一处改动，`render-smoke.mjs` 的替身渲染要跟着支持。
- 面板包版本号要升两处：`package.json` 的 `version` 与 `client.js` 的 `PLUGIN_VERSION`。装进 profile 后重启 DSH 才可见。

- 没有新增脚本，没有新增需要人定期检查的文件。
