fix(panel): 自演进面板文案改为术语 + 补字号尺度 + 重写指标趋势（EV-2026-059 追加）

用户读后反馈三条：判据文案不够专业、字号偏小、指标趋势看不懂且不美观。逐条查根因：

① 文案：初版用修辞（"从未说过「不」""自证过多"），读着顺口但没法当判据名引用，
   也容易被读成价值判断。改为术语，并把标题移进 gates.yaml 作为数据（文案属数据）：
   零否决记录 / 待合入积压 / 预测未复现 / 外部验证占比不足 / 信号来源过度集中 /
   引用路径失效 / 预测口径缺失。读数补点名主体（信号名、失效路径）与百分比形式。
   另修一处渲染缺陷：meaning/action 用 YAML 折叠标量分多行写，句子中间会被插空格
   （实测渲染出"命中率升， 还是"），改为单行。

② 字号：本面板原先**没有字号尺度**——17 个散落的 font-size（8.5–17px）各自为政，
   最小 8.5px 给了趋势的期间标签，中文在这个尺寸下会糊。补上与「指标」面板同一套
   8 档 --t-* 与 --lh-*（基准 14.5，中文在 11–12px 会糊是那边实测过的教训），
   40 处 font-size 与 13 处行高全部并档，无残留硬编码。同时删掉两轮重做留下的死 CSS
   （FocusStrip 的 ev-focus 一族、旧 sparkline 的 .ev-bar*）。

③ 指标趋势：根因是**口径缺陷不是美学**——collect_timeline 把 {ok,total} 压成 ok，
   三期 live 的路由准确率"3/3"于是渲染成三根等高的柱子加一个孤零零的「3」，
   metrics.md 那条"比例类指标务必连同分母解读"的纪律在读侧没落实。
   现改为：数据面保留分母（比例类一律 {ok,total}），面板一行一期 × 一列一指标，
   逐格给读数（含量与分母）与相对上期的变化量；读数恒定、分母过小、反馈捕获为 0
   时用一行注记明说"趋势不可读"，不靠柱高差暗示趋势（原则十）。

验证：panel_render_check 272 → 283 条断言全绿，新增断言钉住排版契约（8 档、无硬编码
font-size、最小档 ≥10、基准档 ≥14、与指标面板同值域）与趋势可读性契约（比例带分母、
变化量、恒定/分母过小时必须出注记）；rehearse_evolve_loop 114/114；八条 kb-checks 全绿；
check_panel_tokens 两面板角色集仍一致。

诚实保留：本轮没有在真实浏览器里核验观感（离线闸门只证明"渲染没坏 + 信息在场"），
视觉判断留给用户；这与面板 README 的"视觉类指标改样式时浏览器实测一次"是同一约定。
