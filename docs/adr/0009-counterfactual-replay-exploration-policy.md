# 探索策略：历史树离线重放，先落理论与出口

一条完整的历史记录可以当作精确的重放器用，在不重跑执行的前提下评估另一种探索策略。本决定把这条机制的形式化补进 [设计理论](../spec/design-theory.md)（新增 §4.5），把不新增原则、以及不做可执行部分的理由留档，并给出重评触发条件。

## Context

- 项目的探索策略目前冻结在正文纪律里：候选最多 5 条、连续 2 条 case 未解决即转人工、阶段一只读生成索引、命名空间顺序和追问触发点。它们散落在 `CLAUDE.md` 与各 skill 正文，没有一处可被整体替换或评估。
- 历史已经在盘上。`traces/<session>.yaml` 记录每个决策与依据（`reason`、`excluded_cases`、`kb_rev`）。`scripts/replay_trace.py` 目前只做结构级回放：比对路由与命中 case 是否与历史一致，判行为漂移，不判对错。
- 判定池的规模是自认缺口。`docs/mechanism/rsi-mechanism.md` 缺口四：池子小到配对检验够不到判定线，结论只能落在证据不足。现有对策是 `α_eff = α/(k+1)` 折减与池内容哈希锁，两者都在固定池子上花掉显著性，不增加池子。
- 外部依据。Dream-RSI（Zheng et al. 2026，arXiv 2609.14858）把探索策略做成可替换的代码，用已完成的历史树对其离线评分，零额外执行；同时报告一个负结果，把历史抽象成方向性洞见注入提示词，在同等预算下一致地不如不注入。
- 数据现状。本机几乎没有可用 traces，其他部署机有。任何依赖历史样本的机制在本机都无法验证。

## Decision

1. 设计理论新增 §4.5，承载四条形式化结论：重放的评分式、代价在覆盖面而不在精度、前置条件是策略可重算、现任策略进候选集只给池上不劣化。同时 §3 补一段强先验压低多样性，§6 补一段评估样本的边际成本近零，§8 的待实现标准由四条变五条（加零执行清算），§11 增一条 limitation（效力上限是反馈覆盖）。引用记 Dream-RSI。
2. 不新增第十二条设计原则。理由是新原则必须从领域约束推导且已有真实使用记录，而这一条目前只有一篇外部论文与一次形式化，没有本项目自己的使用检验；它同时可以作为第十一条的落地条款存在，因此补强第十一条（拒绝域必须包含现任做法本身），不另立条文。
3. 不做可执行部分。不写离线清算脚本，不抽策略旋钮表，不改沉淀流程。理由是本机没有样本可验，自造历史树只能自证，与设计原则一（验证先于交付）和第十条（诚实退化）冲突。落地以设计与出口的形态交付：外部依据表一行、评估池扩容的蓝图行、roadmap 待定池两条带闸门的条目。
4. 不新增 EV 卡。本轮没有实现或修改任何机制，改的是理论层与计划层；等闸门满足、真去改脚本时，再按机制变更流程立卡。

## Rejected / Deferred

- 新增第十二条原则（否决）：时机未到，理由见 Decision 第 2 条。
- 策略旋钮表（推迟，主动选择）：把散落的探索常数收成一张可核对表，本身成本低，但它的价值来自被实测数据回填，先建等于把猜测写成清单。等零执行清算的闸门满足时一起做。
- 用吸收后的历史样本扩充判定池（否决）：答案已经进知识库，样本变成 self_consistent，测不出检索与判断力，只能进回归池。这条区分已写进 eval-arena 的蓝图行。
- 把单机历史当作完整支持集（否决）：支持集是那台机器遇到过的分支，缺的分支在任何重放里都不存在。覆盖面只能靠跨机汇集。
- 学习型探索策略（否决）：不可重算即不可离线清算，且引入新的静默失败组件，违反公理 A4 给出的可靠性纪律。

## 重评触发条件

出现以下任一情况时重开本决策，否则不进入阶段池：

- 任一部署机的 `traces/` 达到 30 条，且反馈捕获率大于 0（捕获率现在贴地，读数见指标体检器）；
- 探索常数被实测数据回填两次以上，说明旋钮表已经有消费者；
- eval-arena 的门控再次落在证据不足，且原因仍然只有池子规模（缺口四复发）；
- 部署机数量达到 3 台以上，跨机汇集历史从设想变成可用做法。
