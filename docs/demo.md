# 演示讲稿：一条 case 的生命（intake → 周审 → 门控 → 闭环）

约 15 分钟的演示，展示知识从一份调查笔记到进入知识库、被门控审查、最终让下一次诊断直接命中的全流程。可现场操作，也可直接回放 [PR #1](https://github.com/pillumina/ascend-sleuth/pull/1) 的记录讲解。

开场一句话：**这是一个会自我变准的诊断知识库——知识从每次问题定位中沉淀，经周审和机器门控入库，下次同类问题直接命中。演示展示这条闭环的每一道关卡。**

## 第一幕：沉淀（约 3 分钟）

**讲**：任何来源的调查——本地 agent 会话、Kimi 对话、手工笔记——都能经 `/skill:to-postmortem` 汇入。agent 提取症状、根因、修复，脱敏后进入待审队列 `postmortems/inbox/`。

**展示**：PR #1 中的 `postmortems/2026-Q3/DEMO-EP-HANG-001.md`——这是审完后转正的形态（指针式：一句话根因 + 指向结构化 case）。强调文件头部的 DEMO 标注：演示数据永不混入真实知识库。

**说**：人的成本被压缩到 30 秒确认，结构化劳动全部由 agent 完成——这是"建议与决定分离"（原则五）的体现。

## 第二幕：周审与预分诊（约 3 分钟）

**展示**：PR #1 的描述正文——就是 groom 周批审清单的实际形态：预分诊结论（new_pattern）、证据（索引中该 namespace 当前 0 条、与在库 case 根因无重叠）、建议的初始置信度（0.3，来自调查质量的 Beta 先验实例化）、高风险检查（无——没碰 expected/compat/common，不需要双签）。

**说**：自动化只产出建议和证据，采纳与否是人批。标签 `kb/new-pattern` 打在 PR 右侧——三分类标签集是路由语言，见 `docs/git-workflow.md`。

## 第三幕：机器门控（约 5 分钟，核心看点）

**讲**：现在看这个系统不依赖任何人的记性的部分。第一次 push 故意犯了一个真实会犯的错——加了 case 忘了重建索引。

**展示**（点开 PR 的 checks 或评论里的表格）：

1. [run 32921725827](https://github.com/pillumina/ascend-sleuth/actions/runs/32921725827)：**红灯**。`build_index.py --check` 检出新增 case 未反映进 `knowledge/_index.yaml`。
2. [run 32921774039](https://github.com/pillumina/ascend-sleuth/actions/runs/32921774039)：补齐索引后**绿灯**。

**说**：为什么这是硬门——索引是诊断第一阶段唯一的加载入口；索引与库不一致，后续诊断就在用过期视图做判断。CI 红线是这个不变量的确定性执行者。**拦截发生在合入前，不是事后通知**。这一条对应原则二（不变量写进结构）和原则六（机器可判、错误无歧义的检查设硬门）。

**补充讲**（流程演示，本次不开真实权限）：owner 落实后，`CODEOWNERS` + 分支保护让审批也变硬门——`knowledge/training/` 的变更必须训练 owner 批；高风险变更（改 expected、动 common/）需要两个 owner 双签。当前是"机制先行、权限后紧"的阶段，占位文件已就绪。

## 第四幕：闭环（约 3 分钟）

**讲**：如果这个 PR 被批准合并，会发生什么——索引随批进入 main；下一个工程师带着同样症状来诊断（"EP 训练 step 3000 hang，all_to_all timeout，world_size 128"），triage 路由到 `training/mindspeed-llm/`，阶段一读索引命中本 case，diagnosis checks 验证 `HCCL_BUFFSIZE` 后给出修复 + rollback；工程师应用后回报结果，case 的命中数 +1，置信度被校准——这就是学习闭环（理论 §4.3：快环回写置信，慢环改知识本身）。

**说**：全程每个步骤都写 trace。万一误诊，trace 能区分"知识错了"还是"执行错了"——前者改库，后者改流程，不会改坏本来正确的知识。

**展示**（可选）：`docs/design-theory.md` §4.3 的两级闭环图，或 `docs/evolution.md` 的演化回路。

## 第五幕：为什么这套流程合理（约 1 分钟）

每道关卡对应一条设计原则，没有一步是装饰：

| 演示环节 | 原则 | 一句话 |
|---|---|---|
| to-postmortem 30 秒确认 | 五 建议与决定分离 | agent 提取，人判定 |
| 周批审 + 预分诊证据 | 八 可观测先于改进 | 建议附证据，决定留记录 |
| CI 红灯拦住不完整变更 | 二 不变量写进结构 | 索引新鲜度不靠记性 |
| 高风险双签（流程） | 六 闸门硬度匹配代价 | 无界损失的变更多一道人 |
| PR 不合并、demo 不污染 | 十 诚实退化 | 演示数据明确标注、永不入库 |
| 合入后下次命中 | 十一 数据触发演进 | 知识随使用变准 |

## 现场问答预案

- **"为什么不直接让 agent 自动入库？"**——原则五：自动化止于建议。错误知识入库的代价（污染后续所有诊断）远大于 30 秒人审。
- **"CI 只检查索引，谁来检查内容对不对？"**——语义正确性机器判不了（原则六的诚实边界），由周批审的人闸 + 语义校验（regex 在真实日志上能否匹配）承担；上线后由 feedback 闭环持续检验。
- **"人审烦了怎么办？"**——注意力是预算（原则九）：批处理、单条 30 秒、停留标红；随机审序对抗疲劳。
- **"规模大了怎么办？"**——`docs/design-theory.md` §10 的三档推演：何时分层路由、何时考虑 embedding（从 Tier 3 进入）、每个升级的触发闸门都已定义。
