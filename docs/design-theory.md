# 设计理论

**论题：一个 agentic 系统是在有界资源上、以概率组件为语义核心、在非平稳世界中持续运作的分级贝叶斯决策机；架构的全部职责，是把决策的可靠性从概率组件的可靠性中解耦出来。**

本文是 [design-principles.md](design-principles.md) 的法理层：十一条原则是律法，本文回答律法从何而来。为了不让推导悬在真空里，全文围绕一个贯穿示例展开——它出现在每一节，每个公式都能在它身上落一次地。

## 0. 一页纸版本

全文可以压成六句话，正文只是它们的展开：

1. **系统在做判断**：面对症状，从一堆候选根因里选出真的那个。判断的本质是概率更新——证据让有的解释更可信、有的更不可信。
2. **错误的代价不对称**：给错修复可能造成不可挽回的损失，多问一句几乎免费。所以一切设计围绕"先验证后交付、代价越大把关越硬"。
3. **判断的资源有限**：模型的上下文窗口和人的审批时间都是硬预算。分层加载、日志裁剪、批审、知识库封顶，全是在给稀缺资源做预算。
4. **整机只有一个部件的失败是静默的**（LLM）：它出错时输出看起来仍然成立。其余组件的失败可观测、可归因。所以关键规则要搬进可观测的那部分——写成结构、脚本、CI，而不是写在 prompt 里盼模型自觉。
5. **世界会漂移**：新平台、新版本、新问题不断出现，所以系统必须自己变准——每次使用更新置信，每次误诊归因改知识或流程，每次架构演进由数据闸门触发。
6. **合起来**：架构的全部职责，是让判断的可靠性不依赖那个静默失败的部件，让变准的动力不依赖任何人的自觉。

需要说明本文自身的地位：它写在系统大规模使用之前。按第 4 章自己的规则，未经使用检验的理论是假设而非结论——本文是这套体系的**第零号假设**，它的公理与推导链同样接受 trace 与 metrics 的检验，被证伪时按演进规则处理。这一条不是谦虚，是体系自洽的必要条件。

## 1. 问题类与四条公理

决策论不适用于一切软件。它适用于一类系统，其成立条件是四条公理：

- **A1 代价不对称**：存在错误后果趋于无界的行动（如污染 checkpoint），而获取证据的成本有限（多问一轮、多跑一条检查）。
- **A2 资源有界**：瓶颈不在算力——模型的上下文窗口与人的注意力都是有限预算。
- **A3 世界非平稳**：症状分布、日志格式、版本组合持续漂移。E 型系统必须持续演化，否则持续变得不满足（Lehman 1980）。
- **A4 失败模式不对称**：语义推理核心（LLM）的失败是**静默的**——输出看起来成立、不留失败痕迹、遵守程度随上下文长度漂移；确定性组件（文件、脚本、CI、git）的失败是**可观测的**——正则写错会被 fallback 兜住，索引过期会被 `--check` 挡住，且失败不随上下文变化。架构利用的是这个不对称，而不是假装确定性组件永不失败。

四条合起来定义的问题类是：后果重大的判断，便宜的证据，昂贵的注意力，会漂移的世界，只有一个部件静默失败的机器。

**贯穿示例**。设想一次这样的事故：128 卡专家并行（EP）训练，在 step 3000 附近 hang，报错日志尾是 `all_to_all timeout`；框架 mindspeed-llm，平台 A5。知识库里恰有一条 case：*HCCL 通信缓冲区在大规模 EP 下不足，症状为 all_to_all_single 在 step 1000 后 hang、world_size ≥ 64，修复为导出环境变量 `HCCL_BUFFSIZE`，severity 标注 service-affecting（需重启生效）*。这个示例是构造的（镜像自 `examples/sample-case.yaml`），但它包含了真实诊断的全部要素。下文称它为 **EP-hang 示例**。

## 2. 判断：证据、信念与行动

系统存在的目的是判断：眼前的症状，哪条根因能够解释。判断需要两个东西——对每个候选根因信到什么程度，以及在此信念下该采取什么行动。

**信念（belief）用概率表示。** 诊断是一个假设集上的推断：候选根因 $h$ 构成假设集，工程师提供的症状、日志、版本信息构成证据（evidence） $e$ 。贝叶斯规则给出证据如何修正信念：

$$P(h \mid e) \;\propto\; P(e \mid h)\cdot P(h)$$

其中 $P(h)$ 是先验（prior）——证据到来前对该根因的预期； $P(e \mid h)$ 是似然（likelihood）——若此根因成立，看到眼前这些症状的可能性。两者相乘再归一化，得到后验（posterior） $P(h \mid e)$。

在 EP-hang 示例上把这个推断走一遍。**先验由两层构成**：triage 把"训练 hang"路由到 `training/mindspeed-llm/`，这是命名空间层的先验——假设集从全部根因收窄到一个目录；候选 case 的 confidence（历史命中记录）是 case 层的先验——一条 18 次命中、1 次误诊的 case，配比从未被使用过的 case 更高的 $P(h)$。（confidence 的精确来历是第 4 章的 Beta 更新；注意它是对"这条 case 靠不靠谱"的信念，不是对"这次是不是它"的判断。）**似然由检索与验证提供**：日志尾的 `all_to_all timeout, world_size=128` 匹配 case 的错误签名，似然上升；随后对照客户环境做诊断检查（见下），是更高信息量的证据。两级加载、候选排序、优雅退化，全部是这套信念管理的工程形态。

**行动用期望损失选择。** 置信本身不是产出；系统必须选择行动。记 $a$ 为候选行动——给出修复、追问一个问题、止损、转人工—— $h$ 为假设， $L(a,h)$ 为损失函数：真实根因是 $h$ 而系统采取行动 $a$ 时付出的代价。Wald 的统计决策准则以期望损失度量行动优劣：

$$a^{*} \;=\; \arg\min_{a}\; \sum_{h} L(a,h)\cdot P(h \mid e)$$

一个行动的期望损失，是它在每种可能现实中的损失按当前信念加权的平均；最优行动是期望损失最小者。比较两个行动时公式退化为 $\Delta(a_1,a_2) = \sum_h [L(a_1,h)-L(a_2,h)]\, P(h \mid e)$ ，只依赖损失差与信念分布——检索与验证的职责是收紧 $P$，闸门与 severity 的职责是正确编码 $L$，任何一侧失真排序即失效。三条推论：

- **推论一（止损 halt）**。若某假设 $h_0$ 下错误修复的损失趋于无穷——比如一条 severity 为 data-loss-risk 的 case 提示"checkpoint 可能已污染"——则无论 $P(h_0 \mid e)$ 多小（只要不为零），给修复的期望损失都被无穷项压倒，最优行动是止损：停机、保现场、通知 owner。（严格地说，损失真正无界时期望计算本身退化，工程上的硬闸是对这个病态的务实处理——设计决策，而非数学推导的终点。）EP-hang 示例里那条 case 标注的是 service-affecting：损失有界但需要重启窗口，所以给修复、同时标注副作用，让人协调窗口。
- **推论二（提问）**。信息的价值在于它会改变行动。提问 $q$ 得到答案 $e_q$ 后信念更新，最优损失随之变化。对答案的所有可能取期望，**不问时的最优损失减去问过之后的平均最优损失**，就是这次提问节约的期望损失：

  $$\mathrm{VPI}(q) \;=\; \underbrace{\min_a \mathbb{E}[L \mid e]}_{\text{不问时的最优损失}} \;-\; \underbrace{\mathbb{E}_{e_q}\Big[\min_a \mathbb{E}[L \mid e, e_q]\Big]}_{\text{问过之后的平均最优损失}} \;\geq\; 0$$

  内层取 min 的凹性（Jensen 不等式：对凹函数 $\mathbb{E}[f(X)] \le f(\mathbb{E}[X])$）保证第二项不超过第一项，所以 VPI 恒非负——信息不会让最优决策变差。提问的判据是 $\mathrm{VPI}(q) > c(q)$ 。EP-hang 示例里，"客户的 `HCCL_BUFFSIZE` 当前设的多少"是一个高价值问题——答案直接决定修复是否适用；"机房温度多少"与假设集几乎正交，VPI 趋于零。信息不全时主动问，由此是最优策略而非服务态度；多个问题待问时按单位成本的信息价值排序（第 8 章的待实现标准）。
- **推论三（验证）**。验证是一种特殊的提问：消耗检索成本，换取对后验的收缩。在 A1 的非对称损失下，收缩信念在损失最大的假设上节约的期望损失天然偏大，验证几乎总是划算的。EP-hang 示例里，让客户跑 `env | grep HCCL_BUFFSIZE` 并对照 `expected: >= 4194304`，比任何文本匹配都更接近"此根因下应观察到什么"。**检索筛选候选，验证决定交付**——"匹配度高就交付"等价于在损失最大的地方省略证据。

## 3. 资源约束：信道、多样性与停止规则

上一节的决策机还带着一个乐观假设：证据的获取不计价。公理 A2 否决了这一点。

**上下文是信道。** 经验上，推理质量取决于上下文内的信噪比，而非总量（这是借用 Shannon 的直觉做类比，不是信息论推论）：一份 128 卡全量 profiler 灌进窗口，判别所需的信号被噪声淹没。EP-hang 示例里，只贴失败 rank 的日志尾（含 `all_to_all timeout` 那几行），不贴全量日志——带宽要分配给与判别最相关的片段。三层按需加载同理：索引每条约 70 token，是保住判别信息前提下的压缩编码。知识库有界是同一论证的推论：重复与过期条目是噪声项，库无界增长则信噪比单调不增，检索质量随之衰减——每命名空间 30 条的上限由此而来。**人的注意力同理**：批处理、单条 30 秒审批、fixture 套件上限换血，都是把审批带宽当预算分配。

**级联是多样性的级联。** Ashby 的必要多样性定律：控制器必须具备不小于扰动多样性的多样性（多样性 $D$ 度量可区分响应的对数数量，取对数使级联可加）：

$$D(\text{controller}) \;\geq\; D(\text{disturbance})$$

这是必要条件而非充分——多样性不足则必然失败，充足不保证成功。单一检索器的多样性有限，所以系统把多样性做成四级级联：triage（结构化分支）→ quickly_check（词法判别）→ agent（语义归一，多样性放大器）→ 人（终极储备）。**优雅退化**是检索器多样性不足时的换挡：EP-hang 示例若症状是模糊的"吞吐缓慢下降"、triage 无分支命中，就加载全部命名空间索引交给 quickly_check 与 agent 筛。**串联保护**是多样性耗尽时交还控制权：连续两个候选 case 修复未解决，第三个不试，转人工——截断保证误诊级联概率随尝试次数指数下降。

## 4. 学习与自演进：两层信念更新

前两节的决策机是静态的：信念给定、行动选定、一次结束。公理 A3 说世界在漂移，静态决策机逐渐失准，因此系统必须在两个层面同时更新信念。两级更新构成自演进闭环，也是 [evolution.md](evolution.md) 全部机制的理论生成处。

### 4.1 对象层：知识置信来自使用记录

把"这条 case 被调用后是否解决问题"视为伯努利试验，命中 $\mathrm{hits}$ 次、误诊 $\mathrm{misdiagnoses}$ 次之后，成功概率的后验是 Beta 分布，其均值为点估计：

$$\mathrm{score} = \frac{\mathrm{hits} + \alpha}{\mathrm{hits} + \mathrm{misdiagnoses} + \alpha + \beta}$$

$\alpha,\beta$ 是先验参数。两个极端看清它们的角色：一条从未被使用的 case，score 完全由先验决定（$=\alpha/(\alpha+\beta)$）；一条被使用千百次的 case，先验被数据淹没，score 收敛到原始命中率。**先验负责冷启动的公平起点，数据负责长期校准**——调查质量（investigation_quality）决定新 case 的 $(\alpha,\beta)$：五天详查的沉淀配强先验，随手记录配弱先验。EP-hang 示例里，修复应用后训练恢复，工程师回报结果， $\mathrm{hits}$ 从 18 到 19——第 2 章里那条 case 的先验 $P(h)$ 就是被这里校准的。时间衰减是对旧证据折价：世界漂移后，旧命中对今天的证明力下降。

**校准是本层的关键性质**：声称 0.8 的 case 群应真的约八成解决。校准一旦破坏，第 2 章的全部决策计算都被污染——这是"诚实退化"原则的理论根据。

### 4.2 元层：系统对自身的信念

trace 是关于系统自身的证据流。误诊发生时，"改知识库"与"改流程"是两个竞争假设，判决同样走贝叶斯：

$$P(\text{case错} \mid \text{误诊}) \;\propto\; P(\text{trace} \mid \text{case错})\cdot P(\text{case错})$$

关键在似然项的可分辨性。EP-hang 示例的坏结局版本：修复应用后 hang 依旧。若 trace 显示 quickly_check 按序触发、fallback 正常、诊断检查对照无误——这样的执行过程在"流程正确"假设下自然，在"流程出错"假设下罕见，判决为 case 错，修知识库；若 trace 里出现跳过 fallback、加载错命名空间——那是执行出错的签名，判决为执行错，修流程。**不经 trace 归因的修复等于跳过证据直接改判。** metrics 是元层信念的可计算汇总；不可观测的机制等于元层拒绝更新。

### 4.3 自演进闭环

两级更新合起来构成一个反馈系统：快环（fix 结果 → confidence 回写 → 候选排序变化）把事做对；慢环（trace → 归因 → 改知识或流程 → 结构变化）做对的事。evolution.md 的五个机制全部落在这两个环上。自演进由此是 A3 下决策机的存在条件——不演化的系统等于信念冻结，第 2 章的计算建立在过期先验上。

### 4.4 演化是假设检验

每个改进设想（拆命名空间、改路由、引入 embedding）是一个待检验假设；闸门是拒绝域，数据是检验统计量。"假设换成实测、闸门取代日历"即先验让位于后验。反方向的病态由 A3 定义：按日历排期是不看数据的演化，追随技术趋势是检验不存在的问题。

## 5. 可靠性基座：把不变量从概率搬进结构

以上决策机运行在一台特殊的机器上。公理 A4 说，这台机器的组件失败模式不对称——这个事实对架构的影响比"谁更可靠"深刻得多。

直觉上，串联系统的整体可靠性是各环节的乘积，$R_{\mathrm{sys}} = R_{\mathrm{det}} \times P(\text{LLM 遵循指令})$ ，概率项封顶。但更精确的表述是 A4 的失败模式语言：**确定性规则的失败可观测——正则失效会被 fallback 兜住、索引过期会被 `--check` 挡在合入前、脚本失败非零退出；概率规则的失败静默——模型跳过一个步骤时，输出看起来仍然成立，不留痕迹，且遵守程度随上下文变长而漂移。**

这个不对称给出架构最直接的一条出路：关键规则从静默失败的一侧搬进可观测失败的一侧。EP-hang 示例的诊断全程都在用它：阶段一只读生成索引（不依赖"只读部分字段"的自觉，索引结构本身就限制了加载量）；反馈追踪落在状态文件的 `feedback_pending` 标记上（任何一次诊断或续接启动都会扫描它，不依赖记性）；索引新鲜度由 `--check` 硬校验并接入 CI（提醒会漏，红线不会）。

不对称同时给出第二条出路——**验证边界**：概率组件的每一个输出在成为系统状态之前，跨过一道确定性校验。YAML 草稿过语义校验（regex 在真实日志片段上能否匹配），trace 落盘前过词表校验，索引过 CI。因为 LLM 失败静默，它的输出不能直接信；因为确定性组件失败可观测，它们恰好可以充当验证者。能力的分工也由此确定：模糊表述的语义归一归模型（它是唯一能做语义解码的组件），知识存储与规则校验归确定性基座（词法、可 diff、可回滚）——检索信号用错误签名而非语义向量，完整论证见 [ADR-0002](adr/0002-retrieval-no-rag-lightweight-index.md)。

## 6. 成本与预算：约束下的决策

前几节的公式里，预算与成本以约束的形式反复出现。本节把它们拉到前台：这些变量对应哪些真实量（附录 A 给出完整对照表），它们如何构成权衡，又如何回流驱动演化。

§2 的决策公式默认行动不计价；真实的行动各有所耗。把资源约束装回决策公式：

$$a^{*} \;=\; \arg\min_{a}\; \sum_{h} L(a,h)\, P(h \mid e)
\quad \text{s.t.}\quad
\mathrm{ctx}(a) \le B_{\mathrm{ctx}},\;\;
\mathrm{attn}(a) \le B_{\mathrm{attn}},\;\;
\mathrm{cost}(a) \le C$$

最优行动的精确含义变为：**预算内**期望损失最小者。第 3 章的全部机制（分层加载、日志裁剪、批审、封顶）都是这个规划在各自维度的解。

约束优化有等价形式，把权衡变成显式的价格。对每个预算引入拉格朗日乘子（影子价格，shadow price） $\lambda$ ：

$$\min_a \; \sum_h L(a,h)\, P(h \mid e)
\;+\; \lambda_{\mathrm{ctx}}\,\mathrm{ctx}(a)
\;+\; \lambda_{\mathrm{attn}}\,\mathrm{attn}(a)
\;+\; \lambda_{\mathrm{cost}}\,\mathrm{cost}(a)$$

影子价格的含义直白：一单位资源折多少期望损失，是一切权衡的兑换率。EP-hang 示例里"要不要让客户把那段 2000 行的完整日志贴进来"——值不值，取决于它收紧信念所节约的期望损失是否超过 $\lambda_{\mathrm{ctx}}$ 乘以它占用的 token；一个 case 值不值得人审 30 秒，取决于 $\lambda_{\mathrm{attn}}$ 乘以 30 秒与误诊期望损失的比较。§2 推论二的 VPI 判据在此显形：提问成本 $c(q)$ 就是提问消耗的预算按影子价格的折价。

**参数回流是演化的输入。** 表中的量起初都是假设（注意力预算估计一小时每周、提问成本估计分钟级），随使用被 metrics 逐个实测（反馈捕获率、批审实际耗时、severity 分布、区域命中率）。实测值代入重解规划，最优解漂移，架构跟着调整：注意力比预想紧，自动化预分诊的价值上升；上下文宽裕，加载策略可以更激进；某区域命中率持续高，闸门按第 10 章的规则收紧。**架构演化 = 约束优化的解随参数实测值回流而重算**——这是 §4.4 在成本维度的实例：被检验的假设，包括成本参数本身。评审时这张表还有一个用途：只在一个变量上变好而把代价推给无预算科目的变更（如让人审无限堆积），不是改善而是转移成本。

## 7. 从理论到设计：义务的收拢

第 2 至 6 章的叙述推导在各章落成了具体的工程义务；本章把它们收拢为一张总表，作为理论与 design-principles.md 条文之间的索引。读法：每条原则由哪些公式或机制推导而来，脚踩哪条公理。

| 原则 | 推导来源 | 公理 |
|---|---|---|
| 一 验证先于交付 | 期望损失准则推论三（验证的 VPI 在非对称损失下天然偏大）与推论一（止损） | A1 |
| 二 不变量写进结构 | 失败模式不对称：静默失败的规则搬进可观测失败的一侧 | A4 |
| 三 agent 语义、底座词法 | 验证边界与能力分工（语义归模型，存储校验归基座） | A4 |
| 四 知识库有界 | 信噪比随规模单调不增；索引单次加载的信道前提 | A2 |
| 五 建议与决定分离 | 损失承担者持有决策权（不承担损失无法正确校准 $L$） | A1 |
| 六 闸门硬度匹配代价 | $L_{\mathrm{mis}}/L_{\mathrm{miss}}$ 比值：无界损失硬拦，漏判代价高处软降级 | A1 |
| 七 变更可逆 | 可逆性给损失设上界；非平稳保证错误必然发生 | A1+A3 |
| 八 可观测先于改进 | 元层更新依赖证据流（无 trace 则归因不可能） | A3 |
| 九 稀缺资源显式预算 | 信道与注意力双约束的显式定价 | A2 |
| 十 诚实退化 | 校准性质：虚报污染全部下游决策计算 | A3 ¹ |

¹ 原则十亦有 A1 血统：虚报直接抬高误判风险。主映射取 A3，因校准属于学习层、学习因非平稳而存在。
| 十一 数据触发演进 | 演化即假设检验，闸门即拒绝域 | A3 |

两点保留的限定。其一，理论推导出的是**定性的义务**，不是定量的设计——30 条上限、30 秒批审、$n=2$ 截断这些常数是参数估计（第 6 章），接受实测重校，不在推导链内。其二，元承诺照旧：一条原则追溯不上这个链条，应当怀疑原则；一个真实选型无法被链条解释，应当修订理论。

## 8. 理论的预言力：尚未实现的设计标准

推导证明理论解释现状；理论更重要的价值是预言现状的缺口——公理会生成系统还没有实现的标准。以下四条由公理直接生成，依设计原则的修订门槛（未经使用检验的规则不足以成为规则）记入 roadmap 待定池：

1. **VPI 序提问**：信息不全时的提问按 $\mathrm{VPI}(q)/c(q)$ 排序——推论二的直接工程化。
2. **校准度量**：confidence 需要 reliability 式校准指标（声称 0.8 的 case 群是否真的约八成解决）——§4.1 校准性质的度量落实。
3. **先验超参显式化**：investigation_quality 到初始 score 的映射作为 $(\alpha,\beta)$ 显式管理——参数不应是隐藏的魔法数。
4. **多样性审计**：triage 分支数与 quickly_check 判别力对照症状空间定期审计——必要多样性定律的可操作化。

## 9. 适用范围：这套理论能指导什么系统

四条公理的概括——概率核心、非对称损失、有界资源、非平稳世界——方向正确但太粗，直接套用容易自我说服。把判据落到可操作的层面，一个系统适用本理论，当且仅当以下四条同时成立。

第一，核心任务是一次性判断。系统在明确的选项之间做一次选择——分类、诊断、路由、审批都是。这是 Wald 框架的地基：单步损失可定义、可比较，期望损失才有意义。多轮交互任务（对话、规划）每步损失互相纠缠，公式没有落点。

第二，假设集可枚举且相对稳定。Bayes 更新在离散候选集上进行——case 库、runbook、规则表都满足。假设空间开放的系统（如通用代码生成），理论只覆盖"从候选中选"的后半段，候选从哪里来在理论之外（第 11 章 limitation 一）。

第三，错误可观测且延迟可接受。confidence 校准依赖结果回流。错误数月后才暴露、或无法归因到单次决策的域，快环失效，理论价值折半。

第四，扰动非对抗性。对手不因被观察而改变行为——硬件故障满足，市场参与者不满足。对抗场景需要博弈论扩展。

用这四条检验几类常见系统。Code review agent 是最直接的同类：判断是接受或拒绝，缺陷模式可枚举，漏报误报即时可观测，缺陷不作策略——四条全满足，且"自动合入破坏性变更"的无界损失立即推出止于建议的边界。Incident response 系统与本系统近乎同构：runbook 对应 case 库，升级链对应多样性级联，复盘对应 postmortem——一个 runbook 管理得好的 on-call 团队，几乎是在无形式化状态下凭经验重演了本理论的义务。Support ticket routing 是最平凡的实例，四条全满足但损失不对称较弱，理论增值也最小。代码生成 agent 只满足一半：单步判断可用，但缺陷假设空间开放——理论覆盖从已知模式中检索，不覆盖发现前所未有的模式，后者仍依赖模型的归纳能力。自动交易在第三、四条上失败：反馈延迟且市场是对手。通用对话 agent 在第一条上失败：没有损失矩阵。

判据也规定了误用的形态：四条任何一条不成立时套用本理论，得到的推导只有修辞价值——看起来严谨，但没有约束力，因为脚下的公式并不成立。

## 10. 选型与规模：理论如何重算架构

前九章用公理解释既有设计；本章演示理论的另一个用途——当选型前提变化时，沿公理重新计算，而不是回到偏好争论。

### 10.1 选型即定价：向量检索的例子

检索在第 2 章中是先验计算 $P(\mathrm{ns} \mid \text{症状})$ 的实现；向量检索只是实现方式之一。理论不禁止任何实现，但按公理给每种实现计价：

| 维度 | 向量检索的价 | 计价公理 |
|---|---|---|
| 信噪比 | 同义词召回提升，但精确错误签名被语义空间模糊——似然项引入噪声 | A2 |
| 可归因性 | 索引不可 diff → 检索决策失去审计链 → 慢环降级 | A3 |
| 可靠性 | 引入新的静默失败组件，未过验证边界 | A4 |
| 多样性 | 响应种类增加（唯一的正项） | A2 |

规则：仅当约束瓶颈是多样性（同义词召回不足）、且该层对审计的依赖低时，向量检索净收益为正。若引入，从 Tier 3（假设生成层）先于 Tier 2（候选过滤层）——Tier 3 的产物由人和 agent 深度排查消化，无闸门被旁路；Tier 2 的噪声进入候选集，虽被验证闸门兜住，收益本就有限。ADR-0002 的"不上"是当前规模（约 600 条上限）下四项计价全负的结论，不是永久禁令。

### 10.2 规模三档推演

设 $N_{\mathrm{ns}}$ 为活跃命名空间数，每命名空间 cap 30 条不随规模改变，变化的只有 $N_{\mathrm{ns}}$ 与扰动多样性。

**档位 0：当前 → $N_{\mathrm{ns}} \approx 20$（总条数 ~600）**。每次诊断的信道成本约 2-6K token，优雅退化全量索引 20-40K，均在预算内。设计区间内无新机制。

**档位 1： $N_{\mathrm{ns}} \approx 20 \to 100$（总条数 ~3K）**。约束从检索转移到路由：triage 的 30 分支正则固定，扰动多样性随领域变宽——必要多样性定律预言路由准确率下降、优雅退化触发频率上升；且退化成本在 $N_{\mathrm{ns}}=100$ 时约 210K token，击穿上下文预算。候选机制排序：**分层 triage**（两级路由，容量 $30\times30=900$）第一——多样性扩容且留在可观测失败的一侧；**学习型路由**第二——多样性无上限但引入新的静默失败组件，须包验证边界（训练数据来自 trace、变更走双签、准确率监控、确定性 fallback 常备），与前项叠加而非替代；**拆仓**仅当瓶颈是审批带宽或组织边界——那是 A2 的另一个变量在绑定，与多样性无关。

**档位 2：总条数 $3\mathrm{K} \to 30\mathrm{K}$**。路由解决后 Tier 2 无恙；压力转移到 Tier 3——语料数万篇时 grep 的瓶颈不是速度而是召回，此时计价表中多样性项开始占优，embedding 从 Tier 3 进入的净收益转正（ADR-0002 触发条件 2 的位置）。Tier 2 保持词法：闸门后置使检索噪声的边际代价低、收益也低，而审计链的损失是全额的。

### 10.3 动态闸门：闸门硬度是知识密度的函数

新平台或新问题类刚出现时，知识库里关于它的 case 极少；随着使用，区域知识密度上升。闸门松紧应跟着密度走：

$$\text{闸门硬度} \;=\; f(\text{局部知识密度})\;:\;\text{冷区软，成熟区硬}$$

推导：区域刚出现时候选本来就少，唯一候选因版本略有出入被硬性排除，结果是问题转人工——漏判损失此时极高，误诊损失因下游验证兜底而有限，比值决定应当软（降置信度、不排除）。ADR-0001 的软版本匹配就是这条规则在版本维度上的实例。区域 case 积累、替代候选出现后，比值反转，闸门可以且应该收紧。例外：severity 闸门对应的损失趋于无穷，与密度无关，永远硬。收紧时机可实测：metrics 里按区域的命中率分布就是知识密度的可观测量。

## 11. 边界与 Limitations

本章回答理论真实地停在哪里。**边界**是有意不覆盖的领域（舍弃是判断）；**limitations** 是想覆盖但当前形式化没做到的地方（诚实欠账，也是后续深化的入口）。二者不进 roadmap——它们是理论陈述，不是工程任务。

### 边界（有意不覆盖）

组织行为与激励是治理问题不是决策问题——工程师愿不愿意沉淀知识，机制只能让"愿意之后"变便宜。CBR 文献的经验结论（负案例、能力边界分布）可作工程启发，但推不出四公理，不入体系。创作与探索类任务没有损失矩阵，决策论无从谈起。对抗场景需要博弈论，本系统的对手是硬件，不作策略。

还有一个更根本的定位：**软件设计是各类 tradeoff，本理论不消灭 tradeoff，只给它定价**。CAP、抽象与性能、交付速度与质量——这些经典权衡不因本文失效。理论做的事情窄得多：在适用域内把各种 tradeoff 统一到期望损失一个计量单位下，让"多贴一段日志"和"多审一个 case"可以比较（影子价格是这个角色的形式化）。定价还需要参数可信：损失至少要能排序，连排序都做不到的域，公式退化为空转。定价之外的因素——组织政治、上市窗口、团队能力匹配——理论管怎么算，不管算不算数，后者本来就是人的决定。

### Limitations（当前形式化没做到的）

一、**假设生成在理论之外**。理论覆盖"从候选中选"，不覆盖"新根因从哪里来"。Tier 3 和人 + agent 深度排查承担假设生成，靠的是模型归纳能力，理论对它没有公式。新 case 的产生是理论边界外的输入，to-postmortem 用工程手段把它接回来，但"接"这个动作不在推导链里。

二、**独立性假设过强**。Beta-Bernoulli 假设每次使用独立同分布，现实中不成立：同一根因的多份记录、客户集群相似导致的命中相关。后果是 confidence 的收敛速度被高估——score 看起来稳定得比实际更快。groom 的去重降低相关性，但这是工程补丁，理论没有解决。

三、**损失矩阵被假设为静态**。 $L$ 不随时间变的假设在长周期上失真：误诊损失随客户重要性、生产阶段漂移。§10.3 的动态闸门在一个维度上开了口子，完整的非平稳损失没有形式化。

四、**人的建模是黑箱**。注意力作为预算处理了，但审批质量随疲劳、随信任积累的漂移没有刻画——Bainbridge 的自动化悖论（自动化越好人越生疏）只有随机审序、深审清单这类工程缓解，理论层面空白。

五、**多样性 $D$ 不可直接度量**。必要多样性定律被反复使用，但"症状空间到底多大"没有可操作的测量方案——第 8 章待定池的多样性审计条目就是这个缺口的存在自认。

六、**单 agent 假设**。多 agent 协作诊断（分布式信念、agent 间通信成本进损失、共识机制）完全未覆盖。当前系统单 agent 运行，假设成立；将来引入 subagent 分工时，理论需要扩展而不是直接套用。

这些欠账的处置遵循本文自己的元规则：不假装解决，不掩盖存在，留待真实需要时再形式化——在没有真实多 agent 场景之前预先形式化它，本身就是对 §4.4 的违反。
