# 设计理论

**论题：一个 agentic 系统是在有界资源上、以概率组件为语义核心、在非平稳世界中持续运作的分级贝叶斯决策机；架构的全部职责，是把决策的可靠性从概率组件的可靠性中解耦出来。**

本文是 [design-principles.md](design-principles.md) 的法理层：十一条原则是律法，本文回答律法从何而来——每条原则的条文下都注明其推导出处，理论到法理是逐条生成的，不是事后附会。理论有意表述在 ascend-sleuth 之上的一层抽象：它适用于满足四条公理的任何系统，本系统只是它的一个完整实例（§8 给出外推映射）。修改原则需要 ADR；修改本文同样需要，且推导链必须保持闭合——新增一条无法由公理生成的设计规则，或改动公理而不能重推全部原则，都视为理论失效。

## 1. 问题类与四条公理

决策论不适用于一切软件。它适用于一类系统，其成立条件恰好是四条公理：

- **A1 代价不对称**：存在错误后果趋于无界的行动（如污染 checkpoint），而获取证据的成本有限（多问一轮、多跑一条检查）。
- **A2 资源有界**：两类瓶颈都不在算力——模型的上下文窗口（信道容量）与人的注意力（审批带宽）都是有限预算。
- **A3 世界非平稳**：症状分布、日志格式、版本组合持续漂移。E 型系统必须持续演化，否则持续变得不满足（Lehman）。
- **A4 概率基座**：系统中唯一不可靠的组件是语义推理核心（LLM）；文件、脚本、CI、git 的可靠性视为 1。

四条合起来定义的问题类是：**后果重大的判断，便宜的证据，昂贵的注意力，会漂移的世界，只有一个部件不可靠的机器**。§2 到 §5 依次兑现这四条公理，每条公理各自生成一族架构义务。

## 2. 静态：信念与行动（兑现 A1）

系统存在的目的是判断：哪条根因解释了眼前的症状。判断需要两种表征。

**信念用概率表示。** 诊断面对的问题本质上是一个假设集上的推断：候选根因 $h$ 构成假设集，工程师提供的症状、日志、版本信息构成证据 $e$，系统的任务是输出对每个假设的置信。贝叶斯规则给出证据如何修正置信：

$$P(h \mid e) \;\propto\; P(e \mid h)\cdot P(h)$$

其中 $P(h)$ 是先验——证据到来前对该根因的预期；$P(e \mid h)$ 是似然——若此根因成立，看到眼前这些症状的可能性。两者相乘再归一化，得到后验 $P(h \mid e)$：综合了预期与证据之后的置信。一条根因若能比别人更好地解释眼前的症状，其置信便上升；预期中罕见、又无法解释症状的，置信被压低。

三层检索是这个推断的结构化实例。triage 提供先验：症状类别把假设集从全部命名空间收窄到两三个目录，这是先验分布的离散化。quickly_check 计算似然：错误签名匹配与否，就是 $P(e \mid h)$ 的一次廉价采样。diagnosis checks 注入高信息量证据：对照客户环境的真实验证，比文本匹配更接近"此根因下应观察到什么"的本质。confidence 则是经过使用校准的后验——它的全部合法性来自证据，而非人工设定。两级加载、候选排序、优雅退化，全部是信念管理的工程形态：先验收窄假设集，似然排序候选，强证据最终定谳。

**行动用期望损失选择。** 置信本身不是产出；系统必须选择行动。记 $a$ 为候选行动——给出修复、追问一个问题、halt、转人工——$h$ 为假设，$L(a,h)$ 为损失函数：真实根因是 $h$ 而系统采取行动 $a$ 时付出的代价。Wald 的统计决策准则以期望损失度量每个行动的优劣：

$$a^{*} \;=\; \arg\min_{a}\; \sum_{h} L(a,h)\cdot P(h \mid e)$$

求和遍历所有仍在考虑的根因：一个行动的期望损失，是它在每种可能现实中的损失按当前信念加权的平均。最优行动是期望损失最小者。这个准则把"信多信少"与"做还是不做"接在了一起——信念只决定权重，代价结构决定排序。

直接比较两个行动时，公式退化为更清晰的形式：

$$\Delta(a_1,a_2) = \sum_h \big[L(a_1,h)-L(a_2,h)\big]\, P(h \mid e)$$

$\Delta$ 只依赖两处：各根因上两个行动的损失差，与信念分布。由此可以读出架构的分工——检索与验证的职责是收紧 $P(h\mid e)$，闸门与 severity 的职责是正确编码 $L$；任何一侧失真，排序即失效。这个公式族一次性推出三条设计：

- **推论一（halt）**。若存在一个假设 $h_0$（如 data-loss），使错误修复的损失 $L(\text{fix}, h_0)$ 趋于无穷，则"直接给修复"这一行动的期望损失被无穷项主导，无论 $P(h_0 \mid e)$ 多小——除非它严格为零。而诊断场景中它几乎从不严格为零。于是 $a^{*}$ 唯一地落在"停机保现场"。severity 闸门由此不是谨慎的美德，而是损失函数含无穷项时的解析解。
- **推论二（提问）**。信息的价值不在于减少无知，在于它会改变行动。提问 $q$ 将返回某个答案 $e_q$——回答前未知——信念随之更新为 $P(h \mid e, e_q)$，最优期望损失随之改变。对答案的所有可能取期望，提问后的平均最优损失与不问时的最优损失之差，就是这次提问节约的期望损失，记作 $\mathrm{VPI}(q)$（期望信息价值）：

  $$\mathrm{VPI}(q) = \mathbb{E}_{e_q}\Big[\min_a \mathbb{E}[L \mid e, e_q]\Big] - \min_a \mathbb{E}[L \mid e]$$

  前项是"先对每个可能的答案分别选出最优行动、再按答案概率平均"的平均最优损失，后项是不获得新信息时所能达到的最优。提问的判据是 $\mathrm{VPI}(q) > c(q)$，其中 $c(q)$ 是提问的成本（工程师向客户往返一轮）。当多个问题待问时，按单位成本的信息价值排序。**"信息不全主动问"由此不是服务态度，而是最优策略**；SKILL.md 里"主动问什么"的清单，是这一判据的领域实例化（理想排序见 §8）。
- **推论三（验证）**。验证是一种特殊的提问——它消耗检索成本，换取对后验的收缩。其净价值同样由 $\mathrm{VPI} > c$ 度量：在 A1 的非对称损失下，收缩后验在损失最大的假设上节约的期望损失天然偏大，验证几乎总是划算的。**检索提名、验证放行**不是流程偏好，是期望损失的解。任何"匹配度高即交付"的捷径，都等价于在损失最大的地方省略了证据。

## 3. 约束：信道、多样性与停止（兑现 A2）

§2 的理想决策机可以无限提问、无限验证；A2 否决了这一点——证据的获取本身消耗预算。由此产生第二族义务。

**上下文是信道。** 推理质量单调依赖于上下文内的信噪比（Shannon）：诊断的有效性受限于进入窗口的信息量与噪声之比，而非总量。于是：三层按需加载是压缩编码（索引每条约 70 token，保住判别所需的互信息）；日志裁剪是带宽分配（只保留失败 rank 与栈尾——与判别互信息最大的片段）；知识库有界是信噪比的守恒——重复与过期条目是噪声项，库无界增长则信噪比单调不增，检索质量随之衰减。**知识库上限不是保守，是信道约束的必然。**

**注意力同理**：人的审批带宽按 A2 显式定量——批处理、单条 30 秒、套件上限换血，都是把人的注意力当作预算分配，而非默认消耗。

**级联是多样性的级联。** 控制问题的成立有一个常被忽略的前提：控制器必须具备与扰动相称的响应能力。Ashby 的必要多样性定律将其形式化。多样性 $D$ 度量一个系统可区分行为的对数数量——响应方式的种类数取对数，使级联时多样性可加：

$$D(\text{controller}) \;\geq\; D(\text{disturbance})$$

定律断言：扰动有多少种必须分别对待的类型，控制器就必须有多少种可区分的响应；响应种类少于扰动类型时，必然存在扰动落在控制能力之外。注意这是必要条件而非充分——多样性充足不保证控制成功，多样性不足则必然失败。这恰好符合架构直觉：检索能力不足可以用更多手段补，但没有任何调度技巧能弥补判别力本身的缺失。

单一检索器的多样性有限，所以系统把多样性做成四级级联：triage（结构化分支）→ quickly_check（词法判别）→ agent（语义归一，多样性放大器）→ 人（终极储备）。级联的每一级向上，多样性单调不减。升级不是流程礼貌，是定律的执行：低层多样性不足以覆盖扰动时，切入高层。**优雅退化**（加载全部索引交给 quickly_check 与 agent 筛）是检索器多样性不足时的换挡；**串联保护**（连续两次未解决转人工）是前三级多样性耗尽时向终极储备交还控制权——每一步都是 $D(\text{controller})$ 追赶 $D(\text{disturbance})$ 的动作。

**停止要显式。** 逐个尝试候选 case 的过程是序贯检验（Wald SPRT 的截断形式）：连续 $n$ 次失败即停止自主尝试。截断保证误诊级联的概率随 $n$ 指数下降；$n=2$ 是"级联风险"与"过度升级成本"之间的截断点，可由误诊率数据复核。

## 4. 动态：学习与自演进（兑现 A3）

非平稳公理推出：系统必须在两个层面同时更新信念，否则 §2 的决策机在漂移的世界里逐渐失准。两级更新构成系统的自演进闭环——本节即 [evolution.md](evolution.md) 全部机制的理论生成处。

### 4.1 对象层：知识置信是后验

一条 case 的可信度不是一个设定值，而是随使用记录更新的分布。把"这条 case 被调用后是否解决问题"视为伯努利试验，命中为成功：$\mathrm{hits}$ 次成功、$\mathrm{misdiagnoses}$ 次失败之后，成功概率的后验分布是 Beta 分布，其均值给出点估计：

$$\mathrm{score} = \frac{\mathrm{hits} + \alpha}{\mathrm{hits} + \mathrm{misdiagnoses} + \alpha + \beta}$$

其中 $\alpha,\beta$ 是先验参数，代表使用记录之外的初始立场。参数的含义由两个极端看清：一条从未被使用的 case（分子分母的计数字皆为 0），score 完全由先验决定，等于 $\alpha/(\alpha+\beta)$；一条被使用千百次的 case，先验被数据淹没，score 收敛到原始命中率 $\mathrm{hits}/(\mathrm{hits}+\mathrm{misdiagnoses})$。**先验负责冷启动时的公平起点，数据负责长期的真实校准**——调查质量（investigation_quality）由此获得了精确的角色定位：它决定新 case 的 $(\alpha,\beta)$，五天详查的高质量沉淀配强先验（起点高、收敛慢），随手记录配弱先验（起点低、迅速被使用记录纠正）。时间衰减则是对旧证据折价：世界漂移后，旧命中对今天的证明力下降，等价于缩小计数刻度。

**校准是本层的关键性质**：声称 $0.8$ 的 case 群应真的约八成解决。校准一旦破坏，§2 的全部决策计算都被毒化——这是"诚实退化"原则的理论根据。

### 4.2 元层：系统对自身的信念

trace 是关于系统自身的证据流。误诊发生时，"改知识库"与"改流程"是两个竞争假设，判决同样走贝叶斯：证据是 trace 记录的执行过程本身。

$$P(\text{case错} \mid \text{误诊}) \;\propto\; P(\text{trace} \mid \text{case错})\cdot P(\text{case错})$$

关键在似然项的可分辨性：若 trace 显示检索按序执行、fallback 正常触发、检查项对照无误，而根因判断错误——这样的执行过程在"流程正确"假设下是自然的，在"流程出错"假设下反而罕见，似然比倒向前者，判决为 case 错，修知识库；反之，trace 中出现跳过 fallback、加载错误命名空间、漏标低置信——这些是执行出错的签名，判决为执行错，修流程。**不经 trace 归因的修复等于跳过证据直接改判**——在两个假设间凭直觉选择，正是 §2 所禁止的以先验冒充后验。metrics 是元层信念的可计算汇总；不可观测的机制等于元层拒绝更新，系统对自身的认知停在先验。

### 4.3 自演进闭环

两级更新合起来构成一个完整的反馈系统：

$$\text{对象层（快环）}:\; \text{fix 结果} \to \text{confidence 回写} \to \text{候选排序变化}$$

$$\text{元层（慢环）}:\; \text{trace} \to \text{归因} \to \text{改知识/改流程} \to \text{结构变化}$$

快环对应单环学习（把事做对），慢环对应双环学习（做对的事）；evolution.md 的五个机制全部落在这两个环上：置信度校准是快环，知识注入与误诊归因是慢环的输入与判决，退休复活与结构演化是慢环对知识形态的维护。**自演进不是附加特性，是 A3 下决策机的存在条件**——不演化的系统在漂移世界里等价于一个信念冻结的决策机，其 §2 计算建立在过期先验上。

### 4.4 演化是假设检验

每个改进设想（拆命名空间、改路由、引入 embedding）是一个待检验假设；闸门是拒绝域，数据是检验统计量：

$$\text{立项} \iff \text{检验统计量越过闸门}$$

"假设换成实测、闸门取代日历"即先验让位于后验。反方向的病态同样由 A3 定义：按日历排期是不看数据的演化，追随技术趋势是检验不存在的问题——两者都在非平稳世界里制造了未经检验的变更。

## 5. 基座：可靠性解耦（兑现 A4）

以上理论描述的是理想决策机；它恰好运行在一台特殊的机器上——除语义核心外一切组件可靠。系统的各环节是串联的：任何一处失效都导致整体失效，因此整体可靠性是各环节可靠性的乘积，而非平均值：

$$R_{\text{sys}} \;=\; R_{\text{det}} \times P(\text{LLM 遵循指令})$$

$R_{\text{det}}$ 是确定性部分的可靠性——文件、脚本、CI、git，按公理 A4 取 1。$P(\text{LLM 遵循})$ 是模型按 SKILL.md 执行的概率，恒小于 1 且无法压到零。乘积的含义是严酷的：**系统可靠性的上限被概率项封顶**——确定性部分做到完美，整体可靠性仍然等于那一项概率；反之，把一条关键规则从概率项搬进确定性项，整体可靠性立即抬升到新的乘积上限。这就是"不变量写进结构"的证明：架构的全部自由度，在于选择每条规则住在哪一项里。

乘积结构给出全部架构自由度：$P(\text{LLM 遵循})$ 不可压到零，唯一的出路是把关键规则从概率项搬进确定性项。这就是"不变量写进结构"的证明——可靠性上限由关键规则依附的层决定，写进结构是确定的，留在自觉里是概率的。

同一条公理从反面给出模型的位置：语义能力是稀缺资源，不可浪费在存储与规则执行上——模糊表述的归一化归模型（它是唯一能做语义解码的组件），知识存储与规则校验归确定性基座（词法、可 diff、可回滚）。**LLM 的每一个输出在成为系统状态之前，都应跨越一道确定性验证边界**——YAML 草稿过语义校验、索引过 CI 校验。这条标准的完整执行尚有缺口（§7）。

## 6. 真实世界的成本变量（A1、A2 的参数化）

§2 与 §3 的公式里有四类变量——$L$（损失）、$c$（证据成本）、预算（信道/注意力）、$R$（可靠性）。它们不是抽象符号，每一个都对应本系统可指认、可度量的真实量。把它们显式命名，公理就从叙述变成可标定的参数表：

| 变量 | 真实指称 | 量级标尺 | 进入哪条公式 |
|---|---|---|---|
| $L_{\text{mis}}$（误诊损失） | 错误 fix 被应用到生产 | 分层：benign（小）< service-affecting（中）< data-loss（$\to\infty$） | §2 期望损失；分层即 severity 的形式化 |
| $L_{\text{miss}}$（漏判损失） | 唯一相关 case 被排除 | 冷启动期高（无替代候选） | §2；与 $L_{\text{mis}}$ 之比决定闸门软硬（原则六） |
| $c_{\text{ask}}$（提问成本） | 工程师向客户多问一轮 | 低（分钟级往返） | §2 推论二的门槛 |
| $c_{\text{retrieve}}$（检索成本） | 读索引、grep Tier 3 | 极低（token 计） | §3 信道预算；两级加载是它的最小化 |
| $B_{\text{ctx}}$（上下文预算） | 模型窗口中的有效推理区间 | ~120K token 的"舒适区" | §3 信噪比约束；日志裁剪是对它的分配 |
| $B_{\text{attn}}$（注意力预算） | owner 每周可投入的审批带宽 | ~1 人·小时/周 | §3；批处理与套件上限是对它的分配 |
| $c_{\text{change}}$（变更成本） | 知识变更的评审+合入开销 | 中（PR + 人审） | §4.4；闸门高度与其联动（变更越贵，门槛越高） |
| $R$（可靠性） | 各层规则遵守的概率 | 确定性层 = 1，LLM 层 < 1 | §5 乘积 |

这张表是理论与工程的对账单，有三个用途。**设计时**：引入新机制前先问它动用了哪个变量、消耗了谁的预算——说不清的不立项。**运营时**：$B_{\text{attn}}$ 与 $L_{\text{mis}}$ 分层是可实测的（metrics 的反馈捕获率、severity 分布），实测值回来后闸门数值按 §4.4 重校。**评审时**：判断一个变更是"改善"还是"转移成本"，只看它把哪个变量变小、把哪个变大——只在一个变量上变好而把代价推给无预算科目（如让人审无限堆积）的变更，不是改善。

## 7. 推导检验：公理 → 十一条原则

| 原则 | 生成来源 |
|---|---|
| 一 验证先于交付 | §2 推论三 + 推论一（非对称损失下的 VPI 与 halt） |
| 二 不变量写进结构 | §5 乘积可靠性 |
| 三 agent 语义、底座词法 | §5 能力各居其位 + §3 信道守恒 |
| 四 知识库有界 | §3 信噪比单调性 + A2 |
| 五 建议与决定分离 | A1（损失承担者持有决策权：误诊的代价由人承担，决策权随之） |
| 六 闸门硬度匹配代价 | §2（$L_{\text{mis}}/L_{\text{miss}}$ 之比决定判据：无界损失硬拦，漏判代价高处软降级） |
| 七 变更可逆 | A1 + A3（可逆性给损失设置上界；非平稳保证错误必然发生，故需回退路径） |
| 八 可观测先于改进 | §4.2 元层（无证据则无更新） |
| 九 稀缺资源显式预算 | A2 + §3 信道与注意力双约束 |
| 十 诚实退化 | §4.1 校准性质（虚报毒化全部下游决策计算） |
| 十一 数据触发演进 | A3 + §4.4 演化假设检验 |

十一分之十一，每条原则获得了一个"为什么"。检验的另一半同样成立：四条公理没有生成任何一条多余的原则——若未来某原则无法追溯到公理，应当怀疑的是原则而不是补一条公理。

## 8. 预言：理论生成而系统尚未实现的标准

推导检验证明理论解释现状；理论的价值更在于预言现状的缺口。以下四条标准由公理直接生成、当前系统尚未实现，依设计原则的修订门槛（未经使用检验的规则不足以成为规则）记入 roadmap 待定池：

1. **VPI 序提问**：信息不全时的提问应按 $\mathrm{VPI}(q)/c(q)$ 排序——§2 推论二的直接工程化。
2. **校准度量**：confidence 需要 reliability 式校准指标（声称 $0.8$ 的 case 群是否真的约八成解决）——§4.1 校准性质的度量落实，metrics 目前没有它。
3. **先验超参显式化**：investigation_quality 到初始 score 的映射应作为 $(\alpha,\beta)$ 显式管理并记录变更——§4.1 公式的参数不应是隐藏的魔法数。
4. **多样性审计**：triage 分支数与 quickly_check 判别力应对照症状空间定期审计——§3 定律的可操作化，路由准确率是其降级代理。

## 9. 外推：同一内核的其他系统

四条公理定义的问题类不限于诊断。任何满足"概率核心 + 非对称损失 + 有界资源 + 非平稳世界"的软件系统，同一内核生成同一族架构义务：

| 通用义务 | 本系统对应 |
|---|---|
| 无界损失的行动先 halt、后建议 | severity 闸门、advisory 边界 |
| 关键规则搬出概率组件、搬进确定性基座 | 结构承载不变量、验证边界 |
| 存储有界、信噪比守恒 | 知识库上限、groom 去重退休 |
| 损失承担者持决策权，自动化止于建议 | 人审批处理、双签 |
| 多样性级联 + 显式停止 + 升级到人 | 四级检索、串联保护 |
| 双层信念更新（对象层 + 元层） | confidence 回写、trace 归因 |
| 演化走假设检验，闸门即拒绝域 | 数据触发的 roadmap |

例：代码评审 agent（无界损失 = 自动合入破坏性变更，故止于建议）；事故响应系统（runbook 即 case 库，升级链即多样性级联）；任何"建议者不执行"的辅助决策系统。反向判据同样有用：**当四条公理有任何一条不成立——损失对称、资源无界、世界平稳、或系统内没有概率组件——本理论不适用，套用它是误用。**

## 10. 边界

理论有意不覆盖四块，舍弃是判断而非疏漏：

- **组织行为与激励**：工程师是否愿意沉淀知识，是治理与文化问题，不是决策问题。设计原则只处理"愿意之后，机制让沉淀便宜"。
- **CBR 的经验结论**：案例推理文献中的负案例、能力边界分布等经验发现，可作工程启发参考，但不能由四条公理生成，不入体系。
- **开放任务**：损失不可定义或不可比较的创作与探索类任务（写诗、头脑风暴）没有损失矩阵，决策论失效。
- **对手博弈**：存在策略性对手时需引入博弈论扩展；本系统的对手（硬件故障）不作策略，故不需要。
