# 人读 / 审阅文本规范（唯一权威）

## 0 这个文件管什么

**管**：所有"给人看或给人审"的文本怎么写——共用条目见 §1，各面的定制条款见 §3。
**不管**：结构（每类文本的必填字段与章节由各自的模板或 schema 管）与结论准确性（那是诊断、沉淀、评测各自的口径）。

**前提：准确严谨优先于好读。** 当"说人话"与"不漏事实"冲突时，事实优先——见 §2 有意保留的例外。
这条前提也决定了 §4 的红线：任何"为了顺口而删掉可核对信息"的写法都不算合格。

## 1 共用条目（所有面一律遵守）

反例取自本仓库真实出现过的写法，多数来自面板与报告早期版本。

| # | 规则 | 反例 |
|---|---|---|
| 1 | 一条只说一件事，超一个分句就拆行 | "这不等于是没问题：先看覆盖面，没报越界与没被检查是两件事" |
| 2 | 主语用具体对象、谓语用动词 | "验证措辞来自文档 PR"；改成"指南里那句『已按此拓扑验证』出自只改文档的 PR"才读得懂 |
| 3 | 自造代称首次出现即定义 | 为本次诊断临时起的简称（给某个中间状态起的别名）只有写的人看得懂 |
| 4 | 不用比喻与拟人 | "一堵只增不减的墙""改动落在机器的哪一层""这个数高是症状" |
| 5 | 不用对偶与排比（例外：诊断里的排除是事实内容，"根因在 B，不在 A"允许，但要紧跟证据；纯修辞的对仗删掉） | "不是变好了多少，也不是作者想优化什么"；否定式排比"这不仅仅是 A，而是 B" |
| 6 | 不用强调副词 | "唯一真实的负反馈读数""恰好可以充当验证者" |
| 7 | 引号不做强调 | 给「稳定」加引号暗示反讽；「」只用于引用字段名、控件名或原话 |
| 8 | 不自我评价 | "如实标注""不冒充通过""诚实的实验记录"——如实是默认要求，不必声明 |
| 9 | 不凑数：手上两条就写两条 | 三段式排比；为了"看起来完整"补第三条 |
| 10 | 同一个东西从头到尾用同一个词 | 同一对象一会儿叫"自研算子包"、一会儿叫"算子库" |
| 11 | 归因写具体出处 | "有观点认为"→ 写 issue 链接、维护者原话、`文件:行号` |
| 12 | 删填充与过度限定 | "值得注意的是数据显示"→"数据显示"；"可能潜在地"→"可能" |
| 13 | 不用通用积极结论收尾 | "后续将持续优化"→ 删掉，或写成具体的下一步 |
| 14 | 术语优先于修辞，能当判据名引用 | "从未说过不""自证过多""依据已消失"→"零否决记录""外部验证停滞""引用路径失效" |
| 15 | 粗体只给读者要执行的东西 | 开关名、命令、阈值、结论；整段加粗等于没加 |
| 16 | 不写裸 Markdown 星号（写在会被原样渲染或复制的地方） | 面板文案里的 `**重点**` 会显示成字符，并被粘进对话 |
| 17 | 不用空泛大词 | "此外""至关重要""深入探讨""赋能""格局""彰显""持久的""宝贵的""充满活力"——换成具体动词，或直接删 |
| 18 | 不绕开"是"字 | "作为/代表着/充当一个……"→ 直接说"是" |
| 19 | 不滥用破折号 | 破折号改逗号或句号；一段里出现多个就值得重写 |
| 20 | 不写虚假范围 | "从 X 到 Y" 只在 X 与 Y 真在同一尺度时使用 |
| 21 | 不写内联标题垂直列表 | 连续多段"**小标题**：正文"改成小标题或自然段 |
| 22 | 节奏要有变化 | 句长与段落收尾换着来；避免连续同构句式（读起来像模板） |

## 2 有意保留的例外（"说人话"不覆盖它们）

以下四类**故意保留原值**，因为改掉会损失可核查性：

1. **原始字段值与枚举**：`process_friction`、`soft_cap`、`resolved` / `not_resolved` / `partial` 等。
   它们是卡片、`gates.yaml`、`trace-status.yaml` 里的真实取值，改成中文读者对不上原文。
   需要时在展开的技术视图或 tooltip 里给出，不替换正文用词。
2. **仓库内路径与命令**：`scripts/metrics_health.py`、`traces/`、`python3 scripts/...`。
   原样给出，可复制即其价值。
3. **已成术语的比喻**："体检"（`metrics_health.py` / `evolution_health.py` 的输出、`docs/guide/metrics.md` 与面板正文都在用）。
   改它要连脚本输出与文档一起动，收益为零。
4. **证据原值**：`文件:行号`、issue / case 编号、报错原文、数字、算子里程碑名。
   这些是复核锚点——读者要能拿它去重跑一遍。把 `token_dispatcher.py:629` 讲成"某处一段通信代码"，
   读起来顺口，但结论就不可核对了。

## 3 人读面清单：哪些条目共用、哪些要定制

§1 的条目对每一面都适用。下表只回答**该面额外需要什么**（定制条款）以及**有没有机械检查**。

| 面 | 位置 | 读者手上有什么 | 定制条款 | 机械检查 |
|---|---|---|---|---|
| 面板文案 | `dsh-plugins/**` 的 `panel-client.js` | 只看界面，不看正文 | 内部标识符不上屏（枚举名、字段名改中文名）；判据的标题与解释是数据（`proposals/gates.yaml`、`metrics/gates.yaml`），改文案不动代码；文案改了要同步改钉它的断言 | `panel_render_check`（排版与退化路径；行文只钉"无字面 Markdown 星号"一条） |
| 定位报告 | `traces/*.report.md` | 复盘 / 交接 / 学习，不看 trace | 必须展开机制——明知根因也不缩水；篇幅 150–500 行；结构与章节见 `report-template.md`；**结论可核对**（指不回证据的标成推测）与**诚实退化**（没验证就写未验证，不把"看起来像"写成"是"）两条常驻本面；证据原值照抄 | `report_lint.py`（节与图，不看行文） |
| trace 人读字段 | `traces/*.yaml` 的顶层 `summary` 与 agent 的 `output`/`reason` | 打开面板看，没有会话上下文，也没读过报告 | 字段要能独立读懂：首次出现的简称当场展开；`output`（给用户）与 `reason`（决策依据）分开写 | 无 |
| EV 卡 | `proposals/ideas/*.yaml` | 评审要 30 秒判定；groom 要回查 | 判据与结论要让评审不开全文即可判定（`predicted_effect.measure` 的存在理由）；`decisions` 只追加、不改写历史；内部字段名照抄 | `verify_proposals.py`（结构、枚举、字段溯源，不看行文） |
| case / reference 词条 | `knowledge/**`、`references/**` | 工程师检索；agent 载入上下文 | 症状句要能直接当 grep 判据（保留报错原文与算子名）；`root_cause` / `fix` 只写结论与依据，不写推理过程 | `build_index.py`、`verify_references.py`（解析与引用） |
| postmortem | `postmortems/**` | 复盘，并供后续沉淀 | 可观察事实与推断分开写：时间线只放事实，判断另起 | 无 |
| 诊断对话输出 | 会话里 | 现场工程师，要立刻行动 | 4 段必需 + 2 个按需块（见 `skills/diagnose/SKILL.md`）；一件事只说一遍；结论先行 | 无 |
| 对话回复 | 会话里 | 没读过本仓文档，也不在诊断现场 | 两类都要展开：短代号（卡号、事项号、机制名、分组名）与本仓内部术语（只有读过 `docs/` 才这么说的词）；必须保留的原值见 §2，本行不复写那份清单 | 无 |
| PR body / 评审摘要 | `.github/PULL_REQUEST_TEMPLATE.md`、`scripts/render_review_summary.py` | 评审人 | 结构按模板的 `##` 区块；代号写中文含义（`docs/glossary.yaml` 的 `scope` 规则） | `pr-template`、`render_review_summary.py --scan` |
| 指标注记 | `metrics/timeline.d/*.yaml`、exec-log | 看面板趋势 | 读数带分母；趋势不可读时明说不可读，不画等高柱充数 | `verify_metrics.py`、`build_timeline.py --check` |
| skill 与 docs 正文 | `skills/**`、`docs/**`、`README.md`、`CLAUDE.md`、`CONTEXT.md` | agent 载入 + 人读 | skill 正文的行为规则要内联（自包含）；不能出现 ADR 号、日期、卡号这类外部锚点；仓库根的人读文档与 `docs/` 正文同样适用 §1 的共用条目与 §2 的原值例外 | `skill-self-contained`、`docs-index`、`render_review_summary.py --scan`（代号未登记与越界）；§1 的其余条目由**独立预核**对照（三档强度见 [git-workflow.md](../guide/git-workflow.md) 的「评审把手」） |

判定做完不等于接入完成：规范要在**写的那一刻**能被读到，否则等于没有。下表是本仓各面的写点；
改动其中任一处时，先看 §1 与本节对应那一行的定制条款。

| 面 | 写点（已指路） |
|---|---|
| 定位报告 | `skills/diagnose/references/report-template.md` |

| 对话回复 | `CLAUDE.md` 的「对话回复写人话」条（每个会话整份注入，会话开始即读到；本面不另设文件） |

## 4 新面接入时怎么判：共用还是定制

新出现一类给人看的文本时，按顺序问三个问题：

1. **这条规则与"谁读"有关吗？** 无关就**共用**。"不自我评价""不凑数""同一对象用同一个词"对任何读者都成立。
2. **与"读者手上有什么上下文"有关吗？** 有关就**定制**。面板读者不看正文，trace 读者没有会话上下文，报告读者不看 trace——
   这正是定制条款的**唯一合法来源**。凡是不能用"读者手上有什么"解释的定制，都应该退回共用条目。
3. **能不能机械检查？** 能，就把检查写进该面自己的脚本；不能，就留人审，不要在规范里假装能查（见 §5）。

**红线**：以"为了好读"为理由删掉事实、编号、命令或数字的定制，一律不允许。准确严谨优先（§0），
需要保留的原值见 §2。

## 5 哪些能硬化

只有同时满足检查准入三条——①机械可查 ②后果确定 ③复发 ≥2 次——的规则才进 CI。
现状：§1 的二十二条里只有第 16 条（无字面 Markdown 星号）合格——后果确定：星号会原样渲染成字符，
并且出现在可复制的指令里被粘进对话。其余二十一条属判断性规范，对照 §1 与 §3 人审——
**不为"AI 味"造硬门，那是假装硬化（原则六）**。

## 6 与各面文档的关系（单向）

- 本文件是**判定口径的权威**：共用条目有哪些、哪些原值必须保留、每一面共用还是定制、哪些能硬化——以本文件为准。
  各面文档不再各写一份"自己的规范版本"。
- **skill 与 skill 支撑文件是例外，而且必须内联完整条目**。仓库约定 `skills/**` 要自包含到"没有 `docs/` 也能正确执行"，
  `docs/` 只是可选论证层（见 `docs/guide/git-workflow.md` 的「Skill 自包含边界」）。所以进 agent 上下文的面
  （报告、trace、case 词条、诊断对话输出）在自己的 skill 或 `references/` 里内联**完整的共用条目**
  （二十二条 + 必须保留的四类原值），并把本文件标成"可选论证层"。
  同一 skill 内的多个支撑文件之间可以互相指路——它们总是一起分发，例如 trace 的行文口径指向同目录的报告模板。
- **不变量**：内联副本的条目文本以本文件 §1 为准；新增、删除或改写一条共用条目时，同步所有内联副本。
  核对方式（照抄就行，别凭印象）：

  ```bash
  # 把 <关键短语> 换成改动那条的核心词，例如 "空泛大词"、"破折号"、"自造代称"
  grep -rn "<关键短语>" docs skills
  # Windows 上没有 grep（本仓库支持 Windows，见 docs/guide/windows-setup.md）：
  Get-ChildItem docs,skills -Recurse -File | Select-String "<关键短语>"
  ```

  命中处应当是**两个文件**：本文件与 `skills/diagnose/references/report-template.md`。
  本文件里可能不止一条命中（§1 的条目本身，加上本节举的例子词），按文件数看即可；多一个文件或少一个文件都要查清。
  为什么不做成脚本：只有两份全文副本，漂移的后果是文字质量退化而不是确定性故障，且至今只发生过一次——
  按检查准入三条（机械可查 / 后果确定 / 复发 ≥2 次）不合格，不为它新增文件与名字。
- **为什么要有这一篇**：本文件出现前，同一套条目在面板 README「文案规范」、`report-template.md` 第 4 节、
  `diagnosis-trace.md`「行文口径」三处各写一份，措辞与反例各异，"哪些能硬化"还在三处各判一次——
  事实被镜像到多处就会漂移（`docs/_manifest.yaml` 头注记的是同一种病）。
