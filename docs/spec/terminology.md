# 术语表：内部行话、易混词与禁用词

本仓自造过一批行话，同一个概念也在不同文档里换过几种写法。这份表把三类词收在一处：内部行话、同一概念的多写法、明确不再用的禁用词。写给人看的文本按它执行。

读者是写或审 `docs/`、`README.md`、`CLAUDE.md`、方案文档、PR body 与 skill 正文的人。只查某个词是什么意思的人看对应词条即可。

范围：本仓内部术语与禁用词。词句层的通用规则在 [writing-norms.md](writing-norms.md)，篇章结构在 `skills/doc-standards/`，两份都不在本文重复。业界通用词不进表，也不强制替换。

## 1 管什么

只收三类词：

1. **内部行话**：本仓自造、圈外人读不懂的简称（如「夹具」「判词」）。
2. **易混词**：同一个概念在不同文档里有多种写法，读写两端对不上（如 gate 与「验收条件」）。
3. **禁用词**：明确不再用、要改成具体说法的词。

不收录也不替换业界通用词：评估、执行、策略、回放、轨迹、回归、基线、候选、样本、评估集、保留测试集、人工审核。它们在各处含义稳定，进表只会把表撑大。

状态值、代码字段、枚举、命令与路径不在此列：它们照原样保留，见 [writing-norms.md](writing-norms.md) §2。

## 2 不管什么

- 一句话怎么写、标题怎么起、标点怎么排：在 [writing-norms.md](writing-norms.md) §1。
- 一篇文档该有哪些节、按什么顺序：在 `skills/doc-standards/`。
- 字段名、状态值、枚举、路径、命令与报错原文：照原样保留，不替换正文用词。
- 历史档案：`docs/adr/`、`postmortems/`、`proposals/` 的既有文本不追溯；新写的文本按本表。

## 3 条目

### 3.1 禁用词与内部行话

| 禁用词 | 改成 | 说明 |
|---|---|---|
| 夹具 | 固定回归样例、固定样例、保留测试集 | 按语境分：`eval/golden/*.fixture.yaml` 是固定回归样例；`eval/holdout.yaml` 是保留测试集 |
| 判词 | 结论、判定结论 | 评估台的三种结论；字段名 `verdict` 照原样 |
| 两臂 | 基线与候选 | 指对照实验的两侧 |
| 账本 | 记录、评估记录 | `impact.yaml` 写「影响记录」；文件路径不改 |
| 成本轴 | 成本指标 | 成本的一个维度 |
| 收题 | 收尾、结单 | 一单诊断或一轮工作结束 |
| 半硬 | 需人工确认的检查 | 检查本身机械，但要人签字才生效 |
| 硬门 | 强制检查 | 不通过就阻断 |
| 软门 | 警告检查 | 只报告，不阻断 |
| 证据包 | 评估报告 | 一次判定所依据的数据与结论 |
| 落点 | 位置、实现位置 | 某条机制或字段落在哪 |
| 留痕 | 记录、可追溯 | 留下可回查的记录 |
| 收口 | 收尾、定稿 | 一段工作或一篇文档结束 |
| 腐烂 | 过期、退化 | 内容或机制随时间失真 |
| 咬人 | 能报错、会报错 | 检查真的会失败，而不是永远通过 |

### 3.2 一译一义：五个英文词

正文只写右列的中文；左列只出现在代码、路径、命令与字段名里时照原样。

| 英文 | 正文写法 | 保留原值的地方 |
|---|---|---|
| gate | 验收条件、检查条件 | `proposals/gates.yaml`、`metrics/gates.yaml`、`no_regression_scope` 等路径与字段 |
| holdout | 保留测试集 | `eval/holdout.yaml`、`scripts/holdout.py` |
| verdict | 结论 | trace 字段 `verdict` 与取值 `case_error`、`execution_error` |
| ledger | 记录 | `impact.yaml` 写「影响记录」；文件名不改 |
| fixture | 固定回归样例 | `*.fixture.yaml`、`scripts/replay_golden.py` |

### 3.3 多义词：按上下文改，不全局替换

这六个词在不同语境下指不同东西，机械替换会改错意思。

| 词 | 语境与改写 |
|---|---|
| 闸门 | 发布准入写「检查条件」；判定通过写「验收条件」；自动合并的开关写「开关」 |
| 口径 | 数怎么算写「统计规则」；字段含义写「定义」；成本写「记账规则」；阈值写「判定标准」 |
| 闭环 | 机制整体写「循环」；数据流写「反馈流程」；改动回到前两个环写「回落」 |
| 门控 | 发布写「准入检查」；评估台写「验收条件」；CI 写「检查」 |
| 兜底 | 失败时的路径写「降级路径」；主路径之外写「备用方案」；Tier 3 写「最后手段」 |
| 对齐 | 会话第 3 步写「确认目标」；两边数字写「一致」；字段映射写「对应」；远端写「同步」 |

## 4 有意保留的例外

- **状态值**：「蓝图」「已落地」「已否决」「未建」是状态字段的取值，不是比喻，照原样写。
- **代码标识符**：`gate`、`holdout`、`verdict`、`ledger`、`fixture` 出现在字段名、文件名、路径与命令里时照原样；需要解释时在展开的技术视图里给中文，不改正文用词。
- **已成术语的比喻**：「体检」在 `metrics_health.py`、`evolution_health.py` 的输出与面板正文里都在用，改它要连脚本输出一起动，收益为零。
- **历史档案**：`docs/adr/` 与 `postmortems/` 的既有文本不追溯；`proposals/` 是只追加档案，也不改。

## 5 哪几条能机检

只有禁用词能脚本扫描，一条 `grep` 即可。扫描范围是目标文档，命中先判是不是原值（引用旧词、字段名、文件名、本表自身）：

```bash
grep -rnE "夹具|判词|两臂|账本|成本轴|收题|半硬|硬门|软门|证据包|落点|留痕|收口|腐烂|咬人" docs/mechanism docs/spec
```

一译一义与多义词两条只能人审：检查工具判不了语境，也不该标记情态。提交前对着 §3 读一遍改动过的段落，比加一条会误报的扫描更有用。

## 6 与相邻规范的关系

- [writing-norms.md](writing-norms.md) 是词句层判定口径的权威；本表只补它没覆盖的术语，不重复它的条目。
- 篇章结构以 `skills/doc-standards/` 为准。
- 字段、状态值与枚举以各面自己的 schema 为准：trace 在 `skills/diagnose/references/diagnosis-trace.md`，卡在 `proposals/ideas/`，case 在 [case-schema.md](case-schema.md)。
- 记账号的生存范围以 [glossary.yaml](../glossary.yaml) 的 `scope` 字段为准；本表不重复那份名册。

## 7 引用

**规范性引用**：本表要求的目标文档按它执行——[writing-norms.md](writing-norms.md) 的 §1 与 §2 优先于本表；两处冲突时以那两条为准。

**资料性引用**：设计附录 I 的审计计数与处理规则（数字只用于排序，不作为验收指标）；`docs/glossary.yaml` 的记账号名册。
