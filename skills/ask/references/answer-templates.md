# 答案模板

`SKILL.md` §5 按类指向本文件四节；块顺序固定：态 + 一句话 → 表或候选 → 第一动作 → 作用域 → 出处。`<...>` 是待填槽位，现场值配一条取值命令，不用「你贴路径」代替。不写检索过程。

## §0 各块与上限
| 块 | 上限 |
|---|---|
| 态 + 一句话 | ≤60 字 |
| 表或候选 | 查证与术语 ≤4 行 ×45 字；现象 ≤3 行 ×30 字；导览 4 到 6 行 ×22 字 |
| 第一动作 | 1 行 ≤50 字，用户机器上能跑；新手题同一行写在哪跑、看哪一行 |
| 作用域 | ≤35 字，照抄 `applies_to` |
| 出处 | 1 行 |

写前从命中的 1 到 2 个词条抄 3 到 5 条必含项（数字、阈值、判别、取值、状态词），写完逐条核；问「是什么」「默认多少」省第一动作；信息不足以分类时候选前加「我按 训练 × 中断 先答，推理说一声」。

## §1 查证（错误码、变量值、规格数字）
示例：
```
问：日志里那个 6 位码怎么读，我这算不算没装好？
命中 ascend-error-code-structure：
一句话：6 位码三段看：第 1 位级别、第 2 位模块、后 4 位是内部码。
| 级别 | E 错误 / W 告警 / I 提示 |
| 模块 | 第 2 位定组件：1 GE、2 FE、E Runtime |
| 内部码 | 后 4 位 9000 起，属内部错误 |
第一动作：grep -n "<码>" $HOME/ascend/log/debug/plog/plog-pid_*.log；训练节点跑，看 for op 后算子名
作用域：跨平台 × CANN 9.0.0
出处：ascend-error-code-structure（<last_verified>）
```

骨架：
```
问：<用户原话，不改写>
<态> <ref-id>：命中 / 只有相关（最近一条覆盖什么）/ 库里没有 <X> / 无法归类，缺 <哪一项>
一句话：<这个码、这个变量或这个数字是什么>
表或取值：<数字、阈值、两型判别、开关取值，照抄词条>
第一动作：<用户机器上能跑的命令>；<在哪跑、看哪一行>
作用域：<照抄 applies_to；两条取交集>
出处：<ref-id>（<last_verified>）
```

零命中写「库里没有收录 <码或变量名>」，给文档面与 `/skill:diagnose`，不写「一般是」。错误码表没有行而 `_code-gaps.yaml` 有 `seen_in` 的，按「只有相关」写。

## §2 导览（某类问题怎么定位）
示例：
```
问：训练跑起来日志不落盘，一般怎么查？
命中 ascend-log-troubleshooting：
一句话：先按开放形态定日志该落在哪，再按形态、磁盘、进程查。
| 支 | 先看什么 |
|---|---|
| 1 形态 | EP 与应用类先看本机日志目录 |
| 2 系统日志 | 看 messages/syslog 报错 |
| 3 磁盘 | df -h 看日志分区是否写满 |
| 4 进程 | ps -elf 查 slogd 是否在跑 |
| 5 依赖 | ldd 查动态库，再重启日志进程 |
第一动作：ls -la $HOME/ascend/log && df -h $HOME
作用域：跨平台 × 四种开放形态
出处：ascend-log-troubleshooting（<last_verified>）
```

骨架：
```
问：<用户原话>
<态> <ref-id>：
一句话：<这类问题先做什么、再做什么>
| 支 | 先看什么 |
|---|---|
| 1 <支名> | <该步的数字、阈值或判别> |
| 2 <支名> | <该步的数字、阈值或判别> |
| 3 <支名> | <该步的数字、阈值或判别> |
| 4 <支名> | <该步的数字、阈值或判别> |
| 5 <支名> | <该步的数字、阈值或判别> |
第一动作：<一条命令>
作用域：<照抄 applies_to>
出处：<methodology ref-id>（<last_verified>）
```

读完整 `content.flow[]` 的每步 `action` 与 `check`，不只看 `name:`。支照 `overview.md` 给全，每支压到 ≤22 字；超过 6 支才合并，合并时保留各步的判据数字。

## §3 现象转诊（卡住、NaN、慢、精度掉）
示例：
```
问：一个训练任务挂住了，日志没有报错。
只有相关（最近一条 ascend-process-hang-triage，覆盖卡住的分层）：
一句话：先取卡住进程的调用栈，按栈里最后一层分流。
我按 训练 × 中断 先答，推理环境说一声。
候选：
1. 栈里无 CANN 函数 → 任务未下发
2. 栈里有 SendTask → 卡在下发
3. 栈里有 Synchronize → 卡在执行
第一动作：PID=$(pgrep -f 'python.*train\.py' | head -1); asys collect -r=stacktrace --remote=$PID --all --quiet；训练节点跑，看栈尾 CANN 函数名
作用域：跨平台 × 进程卡住一类
出处：ascend-process-hang-triage（<last_verified>）
转诊：要我接着查就开 /skill:diagnose，先贴栈尾。
```

骨架：
```
问：<用户原话，保留现象词>
<态> <ref-id>：
一句话：<先做什么、用哪个信号分流>
默认假设：我按 <负载类型 × 性质> 先答，<另一种> 说一声。
候选：
1. <候选> → <怎么从现场数据区分它>
2. <候选> → <怎么从现场数据区分它>
3. <候选> → <怎么从现场数据区分它>
第一动作：<一条命令，能区分上面几个候选>；<在哪跑、看哪一行>
作用域：<照抄 applies_to>
出处：<methodology ref-id 或 case id>（<last_verified>）
转诊：/skill:diagnose，先贴 <具体那一项>。
```

不出现「原因是」「大概率是」。三个候选要能被同一条命令分开；分不开回 `SKILL.md` 第 4 节重检索。

## §4 术语解释（名词、平台代号）
示例：
```
问：日志里常说的 plog 是什么？
命中 ascend-log-classification：
一句话：plog 是 Host 侧应用进程打的日志，报错先从这里找。
第一动作：grep -n ERROR $HOME/ascend/log/debug/*.log
作用域：跨平台 × EP 形态
出处：ascend-log-classification（<last_verified>）
```

骨架：
```
问：<术语原话>
<态> <ref-id>：
一句话：<这个术语是什么，属于平台、软件栈还是工具>
第一动作：<一条能确认它在本机取值的命令>
作用域：<照抄 applies_to>
出处：<ref-id>（<last_verified>）
```

库里没有这个词时不造解释：写「库里没有收录 <术语>」，给一个最接近的相邻词条 id 与它覆盖什么。

## 反例（三种硬失败）

- 把「没查到」写成「一般是」：错误码表没有这一行时，不许写「这个码一般是通信超时」；写「库里没有收录 <码>」，再给缺口索引的 `seen_in` 或文档面。
- 把症状类答成结论：用户说「任务挂住了」→ 不许写「原因是 HCCL 建链超时」；写候选、一条判别命令、一句转诊。
- 反问用户是哪类人：用户问一个变量的默认值时，不许问「你是新员工还是定位工程师」；直接给默认值与作用域。
