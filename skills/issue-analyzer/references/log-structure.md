# 昇腾日志结构与采集知识

本文件提供昇腾现网日志的类型知识、格式要素与现场采集命令。**注意：不同版本/交付形态的目录结构存在差异，以下"典型形态"仅作提示——实际分析时必须先运行 `log_analyzer.py scan` 自动发现结构，以实际扫描结果为准，禁止假设结构后直接下结论。**

## 一、常见日志类型速览

| 类型 | 典型位置/文件名特征 | 内容 | 排查价值 |
|---|---|---|---|
| plog（平台日志） | `~/ascend/log/plog/`（或 `/var/log/npu/` 等变体），按 host/device 分文件、按时间滚动 | CANN/驱动/运行时日志，含 host 与 device 侧事件 | 主战场：设备故障、运行时错误、HCCL 错误 |
| slog 相关 | slog 守护进程落盘的日志 | 底层系统日志 | plog 的来源之一，通常无需单独看 |
| device 日志 | 文件名含 `device-<id>` | 单卡视角事件（ECC、复位、算子错误） | 定位问题卡 |
| host 日志 | 文件名含 `host` | host 侧运行时/驱动事件 | 与 device 日志交叉验证 |
| dmesg / 内核日志 | `dmesg`、`/var/log/messages` | 内核与驱动事件：OOM killer、PCIe 错误、ECC、设备复位、掉电 | 硬件/系统级问题的第一入口，**强烈建议向用户索取** |
| 训练框架日志 | nohup/screen/torchrun 输出、各 rank 日志、`rank_*/` 目录 | Python 异常栈、框架报错、loss 输出 | 模型/框架侧根因、哪个 rank 先挂 |
| HCCL/分布式日志 | hccl 日志、rank table、hostfile、弹性 agent 日志 | 集合通信初始化与超时 | 集群断联、超时类问题 |
| 推理服务日志 | MindIE/vLLM 服务日志、访问日志 | 请求处理、服务进程状态 | 推理中断、超时雪崩 |
| npu-smi 输出 | 现场命令（非日志文件） | 设备实时状态、健康度、温度、显存 | 问题时刻设备状态（事后日志可能缺失，建议问题复现时采集） |

## 二、日志格式要素

### 2.1 时间戳格式家族

`log_analyzer.py` 已内置自动识别，分析时无需手工指定，但构建时间线、对齐多机日志时需知道常见形态：

| 形态 | 示例 | 常见于 |
|---|---|---|
| 方括号标准式 | `[2026-08-28 10:23:45.123456]` | CANN/框架日志 |
| 空格分隔式 | `2026-08-28 10:23:45.123` | 各类文本日志 |
| 横线连接式 | `2026-08-28-10:23:45.123` | device/slog 日志 |
| 斜杠式 | `2026/08/28 10:23:45` | 部分服务日志 |
| syslog 式 | `Aug 28 10:23:45` | dmesg/messages（无年份，脚本按当前年补齐） |

### 2.2 级别标签

常见级别标签：`[ERROR]`、`[FATAL]`/`[CRITICAL]`、`[WARNING]`/`[WARN]`、`[INFO]`、`[DEBUG]`。也有模块化形式如 `[ERROR:RUNTIME]`、`[WARNING:HCCL]`——模块名是重要的下钻线索。

### 2.3 昇腾错误码形态

昇腾日志中常见**两位大写字母前缀 + 四位数字**的错误码（如 `EE9999`、`EZ9999`、`EI9999` 一类内部错误码），通常伴随错误描述文本。

处理规则（铁律 2 的具体应用）：
1. 提取时保留错误码**原文**（脚本默认模式 `ascend_code` 自动命中）
2. 错误码含义**以官方《错误码参考》文档为准**，不确定时标注"含义待查证"
3. 禁止根据错误码"长得像"某个已知码而编造含义
4. 报告中给出错误码原文 + 日志原文，用户可自行比对官方文档

### 2.4 框架日志特征

- Python 异常栈：`Traceback (most recent call last):` 开头，后续行为无时间戳的续行——`extract` 的时间窗过滤采用"继承上文时间戳"策略，栈行不会被时间窗误伤
- 分布式训练常见标识：rank id、world size、`torch.distributed`、`HCCL`、`NCCL`（混部环境）、elastic agent 日志
- MindSpore 常见标识：`MindSpore`、`INFO:...`、`WARNING:...`

## 三、结构自动发现方法（Step 1 执行要点）

1. 运行 `scan` 后先看 manifest 的整体统计：文件数、总大小、整体时间跨度、类型分布
2. 用 `type` 字段快速判断日志包构成：是否有 device/host 日志？是否有 dmesg？是否有框架日志？
3. 用 `host` 字段（从路径中的 IP/主机名提取）判断是单机还是多机日志包
4. 用 `device` 字段判断覆盖了哪些卡
5. 用 `first_ts/last_ts` 判断日志是否覆盖问题时间窗——**不覆盖时必须告知用户并索取对应时段日志**（铁律 3）
6. 时间戳全为空（first_ts/last_ts 为 null）的文件多为二进制/非日志文件或特殊格式，单独处理

## 四、多机多卡时间对齐（Step 3 执行要点）

跨 host 构建时间线前必须做时钟一致性检查，否则"第一个错误"判断会被时间漂移误导：

1. **基准事件法**：找各 host 日志中都会记录的同一事件（如集群统一的心跳、任务启动广播、HCCL 初始化），比较各 host 记录的时间戳差值
2. **差值阈值**：偏差 <2s 可直接对齐比较；2s~60s 需在时间线中标注"±Xs 时钟偏差"；>60s 或方向不一致（事件顺序颠倒）说明时钟明显漂移，结论必须降级并标注
3. 常见坑：NTP 跳变、某节点时区配置不一致（时间戳看起来差整数小时）、BIOS 时钟与系统时钟不一致
4. 单机多卡场景一般无需此检查（同一时钟域），但 device 日志与 host 日志时间戳粒度可能不同

## 五、现场采集命令速查（向用户索取补充日志时使用）

| 目标 | 命令/方法 | 说明 |
|---|---|---|
| 内核日志 | `dmesg -T > dmesg_$(date +%Y%m%d_%H%M).log` | `-T` 转人类可读时间 |
| 系统日志 | 收集 `/var/log/messages`（或 journalctl 导出：`journalctl --since "<时间>" --until "<时间>" > journal.log`） | OOM killer、服务崩溃记录 |
| 设备状态 | `npu-smi info > npu_smi_info.txt`；异常卡详情 `npu-smi info -t board -i <id>` | 问题时刻状态最准；事后补采也有参考价值 |
| 设备故障历史 | `npu-smi info -t fault -i <id>`（按现场版本支持情况） | ECC/故障记录 |
| plog 打包 | `tar czf plog_$(hostname)_$(date +%Y%m%d).tar.gz ~/ascend/log/plog/` | 打包前可用 `find -newermt` 按时间窗裁剪 |
| 按时间窗裁剪 | `find ~/ascend/log/plog/ -name "*.log" -newermt "2026-08-28 10:00" ! -newermt "2026-08-28 10:40" | tar czf plog_window.tar.gz -T -` | 大日志包建议裁剪后传输 |
| 训练框架日志 | nohup.out/screen 记录、torchrun/agent 日志、各 rank 输出 | 含 Python 栈，定位首个异常 rank |
| 网络状态 | `hccn_tool <id> -ip -g`、`hccn_tool <id> -tls -g`（A3 类）、网卡/光模块检查命令按现场版本 | 通信类问题 |
| 主机信息 | `uptime`、`last reboot`、`cat /etc/os-release`、NPU 型号 | 判断是否发生过重启 |

**索取原则**（铁律 3）：一次性列出全部需要的日志及对应采集命令，注明每项的用途；能给出精确时间窗的让用户按时间窗裁剪后提供。

## 六、常见坑

| 坑 | 现象 | 对策 |
|---|---|---|
| 日志滚动覆盖 | 问题时段日志已被滚动删除/压缩 | 检查 manifest 时间覆盖；缺时段立即索取 |
| 编码混杂 | 同一日志包 UTF-8/GBK 混用，出现乱码 | 脚本已自动探测编码；仍乱码时用 `--patterns` 按错误码/英文关键字提取 |
| 时间戳缺失 | 栈续行、分隔行无时间戳 | 脚本采用"继承上文时间戳"策略过滤；构建时间线时人工核对 |
| 时钟漂移 | 多机时间线顺序错乱 | 见第四节时钟对齐 |
| 混部环境 | 同机存在 NCCL/GPU 日志干扰 | 提取时限定文件范围（`--files`）或按目录 `--dir` 收敛 |
| 日志包嵌套压缩 | tar 内含 tar.gz | 先完整解包到独立目录再 scan，禁止在压缩包内"估计"结构 |
