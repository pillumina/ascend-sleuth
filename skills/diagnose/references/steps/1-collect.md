# 步骤 1：收集症状 + 确认框架（全部来自工程师提供的信息）

> **何时读**：每次诊断，开屏确认不是「只问思路的咨询」之后。
> **完成判据**：覆盖表逐行有值或列为待问项，缺口一次问全并逐值标来源；现场时间线已写进 trace。
> **本步产出**：覆盖表、user 事件的 `evidence`、`incident_timeline` / `incident_env`、负载类型与来源。

> 你不访问任何环境。所有信息（日志、版本、报错、环境变量值）由工程师从客户那提供。信息不够时，明确提示需要向客户要什么。case 里的 `command` 是“要确认的检查”——对照已提供信息判断，或让客户跑后贴回，不是你执行 pip/env/grep。

```
本步的工作是一张**覆盖表**：行固定、值按他提交的材料填——**先提取，再问缺口**，顺序不能反。

固定行（每行一个值，别合并、别省略行）：
  1) 错误原文（字面，不转述）        2) 触发位置（启动 / 第 N 步 / 请求中）
  3) 负载类型（训练 / 推理）          4) 引擎版本
  5) CANN 版本                      6) HDK / 驱动版本
  7) 平台（A2/A3/A5 + 具体型号）      8) 必现还是偶发（复现率）
  9) 单机还是多机（哪些 rank / 节点）  10) 已经试过什么（改过什么、报错有没有变）
  另收环境变量值（HCCL_*/ASCEND_*/NPU_*）——同样先提取。

**性质差异行**（写完上面那张表之后补一次；这几行的填法同样是"先提取、提取不到留空"）：
上面 10 行按「报错了什么」设计，对**中断**够用；性能与精度问题的材料形态不同——它们往往**没有错误原文**，
要的是"手上有什么测量数据"。所以按本轮性质再走一遍证据面，缺的同样一次问全：

性能（`performance`）：
  P1) 有没有 profiling 采集产物（哪个工具采的：msprof / 框架侧 profiler，产物目录形态）
  P2) **是劣化还是从来就慢**——"从来就慢"要的是达标线（期望 step 时间 / 吞吐是多少），
      "劣化"要有**对比基线**：同一任务在变慢之前或另一套环境的 profiling 数据有没有
  P3) 现象的时间形态（持续 / 周期性 / 某个 step 或请求开始）
  P4) 范围（单卡 / 部分 rank / 全集群；单机 / 多机）
精度（`precision`）：
  C1) 有没有 dump / 比对结果（msProbe 的哪一类产物）
  C2) 有没有**标杆**（CPU/GPU/另一版本的同等 dump）——没有标杆就说明"只能判一致性、判不了对错"
  C3) 首次异常位置（loss 曲线第几步开始偏、还是从第一个 step 就错）
  C4) 评价标准（loss 曲线 / 评测集分数 / 逐 token 比对）

**为什么单独列而不并进上面那张表**：这四行对中断类问题是噪声（问"有没有 profiling"会跑偏），
而中断那 10 行里的"错误原文"对性能类问题常常拿不到（**没有错误是常态，不是漏问**）。
两边都保留，按性质取用；**不填的行不记账**，别为凑齐而编值。

**P2 与 C2 是这两组里最容易漏、也最影响结论的两行**：没有基线，"劣化多少"只能靠用户体感；
没有标杆，"精度对不对"与"两次跑得一样不一样"是两件事——漏问它们会让后面的判读失去参照。

怎么填：
  a) 先在他已经贴进来的日志 / 报错 / 配置 / 命令输出里找：栈尾常带框架版本，启动横幅带
     CANN 与 HDK 版本，plog 与 npu-smi 输出带平台，启动脚本带环境变量——**别整份索要**
  b) 提取到的行填值；**提取不到的行留空**——空行本身就是待问项，不靠"我觉得还缺什么"
  c) 只问空着的那几行，一次问全（别挤牙膏式一轮一项）
  d) 把提取到的值列给他核对一次（日志里的版本可能被容器覆盖，提出来不等于事实）

**来源是逐值必填**（与值同时记，不另问一轮）：每个填了值的行都标它从哪来——四档收敛写，
别自造：
  `日志`（栈尾 / plog / 启动横幅，可在材料里复核）｜`命令输出`（他贴的 npu-smi / env 等）
  ｜`配置`（启动脚本、config 文件）｜**`他的描述`**（只出现在他给你的文字里，材料里找不到）
**`他的描述` 是四档里最弱的一档**：容器注入、镜像版本、环境覆盖都可能让它与现场不符，
涉及版本 / 平台 / 卡数这类要拿去匹配 case 的值时，**用一条命令输出复核再定**
（例：CANN 与 HDK 版本只有描述里有时，让他跑一次 `npu-smi info` 或读安装目录的 version 文件）。
没有来源的值等于待核值——归到待问项里，别当已确认。

框架：从提供的信息/报错判断（日志里 mindspeed/vllm 字样等）；判断不了就问工程师
  “客户跑的什么框架”——不要跑 pip list（那是你本地环境，跟客户无关）

**负载类型（训练 / 推理）＝ 路由的第一步**，它决定去库里哪一半找，所以本行的来源要连同值一起记：
  ① 材料里写着 → 直接用：他在说训练/训练任务、在贴训练脚本或 loss 曲线；在贴推理请求、
     服务命令（`vllm serve` / `mindie` 起服务）、吞吐 / 时延；在报一条线上服务的故障
  ② 材料里没有 → **问一句，跟引擎版本并列问，不要单开一轮**——「这单是训练任务还是推理服务？」
     这是他的环境事实，他一定知道；模型去猜这件事既不准也没必要
  ③ 他没单说，但顺手给了框架名 → 直接对到库里目录：`knowledge/training/<框架>/` 还是
     `knowledge/inference/<框架>/`。对得上就用，来源记 `框架`（这就是"负载类型"的第三档来源，
     不是另建一张表——库里的目录本身就是那张表，新框架来了照着放就行）
  ④ 他一时不答 → **负载类型未知不是阻塞项**：训练与推理都查（`common/` 训练与推理都查照旧），
     在 trace 里写 `workload_type: unknown`、`workload_type_source: unknown`，照常往下走
  ⑤ 中途证据与他的说法相反 → **以证据为准**，并回一句让他能改向
     （例：「你说训练，日志里是 `vllm serve`——我按推理走；如果确实是训练请纠我」），
     来源记 `证据`，别把矛盾咽掉
  别做的事：不要从"训练集大小""grad 相关字样"这类间接痕迹推负载类型；也不要因为拿不准就把
  "你觉得这是训练还是推理"抛回去——那句话问的正是他一定知道、而猜不准的那件事。
```

**输出契约：只报确认行与待补项**——已提取到的行**按主题分组报**（平台与卡数一组、版本三件套一组、
框架与部署形态一组，**每组一行、不要三项挤一行**），逐项可核；不把原文复述回去（让他重看自己的日志等于没提）；
**已确认的行带上来源**（`来自日志` / `来自你的描述`），让他一眼看出哪条该复核；空行凑成一条问句问出去，
编号让他回数字或直接补。
形态举例（行按上面固定顺序，⚠ 即待问项；注意版本三件套的来源不一样时怎么标）：

```
信息核对（从你贴的材料里提的，⚠ 的要你补；标「你的描述」的请顺手复核一次）

✓ 平台与卡数：A3 机型 / Ascend 910C / 每节点 8 卡 / 4 机（来自你的描述）
✓ 负载类型：推理（来自配置里的 `vllm serve` 启动命令）
✓ 版本三件套：CANN 8.1.RC1 · HDK 24.1.RC3 · 驱动 24.1.rc3（来自你的描述，未见日志或横幅）
✓ 框架与部署：vLLM + vllm-ascend 均 v0.18.0（来自配置里的 PYTHONPATH）；1P1D，PD 各双机（来自你的描述）
✓ 环境变量：HCCL_SOCKET_IFNAME / HCCL_OP_EXPANSION_MODE / HCCL_BUFFSIZE=512 …（来自配置）

⚠ 触发位置：启动即挂，还是跑起来第几步挂？
⚠ 影响面：必现还是偶发？单机还是多机？
⚠ 已经试过什么？（避免我给你试过的方案）
```

**这张表同时是 trace 的 user 事件 `evidence` 的骨架**：提取值与缺口（`missing`）都落进去，
续接的人不必重问一遍已经给过的信息。

**现场事实同时是一条时间线**：材料里的现象、变更（谁改了什么）、规避与恢复，按发生顺序记进 trace 的
`incident_timeline`——一条一个事实，`at` 照材料精度（只有日期就写日期，没有时点写 `null`）；
平台 / 框架 / 版本 / 部署形态一行记 `incident_env`。上游事件（issue / PR / 维护者答复）不进这段，
进 `upstream_timeline`。字段与粒度见 `../diagnosis-trace.md` 的「现场侧时间线」一节。

**日志裁剪（硬要求）**：诊断 session 的 context 八成是日志/profiler，不是 KB。一份 128 卡全量 profiler 灌进来直接滑出 smart zone（~120K token 推理最锐利），推理质量暴跌。裁剪规则：
- 只贴**失败 rank**的日志（`rank_selector` 指定的：coordinator / all_failed / by_topology）
- 只贴报错**栈尾**（最后 N 行，含第一个 ERROR）
- profiler 数据先过 `ascend-profile-analyze` 出 `report.md`，只读报告不读原始数据

**数据资产探询不在这里**——时点在**步骤 3 候选加载之后**（缺哪个具体值要看过候选才知道）。本步只把"他手上可能有什么测量产物"记一笔到 user 事件。

**发来的是截图时**：模型能读图就直接读；不能读图先请他贴文字；都不行才用 vllm-kb 的 ocr（见 `5-deep-dive.md` 的「vllm-kb」一节）。
